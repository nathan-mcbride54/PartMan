## Verification

The local evidence command is `cargo xtask ci`. The supply-chain command is
`cargo xtask supply-chain` after installing the pinned tools. Neither command
contains privileged or destructive storage behavior. No WP-000 command
enumerates, opens, or writes a block device; the only filesystem reads are of
`.github/workflows/` for the action-pin check.

## Known gaps carried into later work packages

- Section 11.7 requires `docs/traceability/` to be generated by CI. This file is
  hand-maintained. Generation needs the requirement-ID annotations that arrive
  with WP-010, and is tracked there.
- Section 1.10 states that CI enforces path ownership via CODEOWNERS. GitHub
  CODEOWNERS requires review from an owner; it does not reject a diff that
  touches paths outside the work package's assignment. Mechanical enforcement
  needs machine-readable owned-path data in `docs/work-packages/`, which does
  not yet exist for later packages.
- Coverage floors are set at M1 per Section 11.8 and are therefore not
  configured here.
