## Verification

`cargo xtask ci` runs the codec suite at Tier 1. The crate performs no I/O,
launches no process, and never touches storage, so nothing here can reach a host
or user disk.

`cargo xtask cross-language` proves MODEL-005 parity. It runs as its own CI job
rather than inside `cargo xtask ci`, so that Rust-only contributors need no Node
toolchain while the proof still cannot be skipped in CI.

The encoder was differentially checked against the `cborg` oracle named by
ADR-C1. All checked vectors agreed byte-for-byte, including length-first map key
ordering and the `2^53` and `2^64 - 1` boundaries. That run was manual and is
not a CI gate: `cborg` is not a dependency of this repository, and adding one to
the authorization path to test it would defeat the reason it has none.

## Known gaps carried into later increments

- ~~Section 11.4 requires a `cargo-fuzz` target for this decoder.~~ Delivered in increment 4; see below. Scheduled long runs remain outstanding.
  `cargo-fuzz` needs a nightly toolchain, which conflicts with the single pinned
  stable toolchain in `rust-toolchain.toml`; resolving that is part of
  increment 4.
- The Section 5 domain types, MODEL-002 layering, and MODEL-004 provenance are
  not yet modelled; only the encoding they will use exists.
- ~~The `sha2` dependency tree has not been audited for `unsafe`.~~ Audited.
  `generic-array` 78 occurrences, `sha2` 29, `cpufeatures` 9, `block-buffer` 4;
  `digest`, `crypto-common`, and `typenum` declare `forbid(unsafe_code)`.
  SAFE-009 constrains this project's own crates and metadata parsers, not the
  dependency graph, and both are clean. The ADR-C1 verification line that
  demanded otherwise was corrected there rather than quietly dropped.
