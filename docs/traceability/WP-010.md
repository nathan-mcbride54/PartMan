## Verification

`cargo xtask ci` runs the codec suite at Tier 1. The crate performs no I/O,
launches no process, and never touches storage, so nothing here can reach a host
or user disk.

The encoder was differentially checked against the `cborg` oracle named by
ADR-C1. All checked vectors agreed byte-for-byte, including length-first map key
ordering and the `2^53` and `2^64 - 1` boundaries. That run was manual; making it
an automated gate needs the Node toolchain introduced in increment 2 and is
tracked there.

## Known gaps carried into later increments

- MODEL-005 requires Rust and TypeScript to produce identical hashes, proven by
  cross-language golden tests. Only the Rust side exists. The vectors in
  `crates/domain/src/canonical/tests.rs` are the fixture the TypeScript codec
  must reproduce.
- Section 11.4 requires a `cargo-fuzz` target for this decoder. Not yet present.
- The Section 5 domain types, MODEL-002 layering, and MODEL-004 provenance are
  not yet modelled; only the encoding they will use exists.
- ADR-C1 requires confirming that the crate and its dependencies satisfy
  SAFE-009. The domain crate itself is `unsafe`-free by workspace lint; the
  `sha2` dependency tree has not been audited for `unsafe` and is not covered by
  that lint.
