## Verification

The local evidence command is `cargo xtask tokens`, and it also runs inside
`cargo xtask ci`. It reads one JSON file and computes numbers from it. It
contains no privileged or destructive behaviour, enumerates no device, opens no
block device, and launches no process.

The harness prints the tightest contrast pairing and the closest colour-vision
pair it measured, so a pass reports its own margin rather than only its verdict.
At the time of writing those are 3.57:1 against a 3.0 floor, and delta-E 21.9
against a 12.0 floor.

## Known gaps carried into later increments

- **UI-008 is only partially covered.** Contrast is computable from a token
  file; keyboard-only operation, screen-reader semantics, 200% zoom and reduced
  motion are not, and none of them are inspected. They belong to increments 2
  and 3, and **M0's "accessibility harness runs" criterion should be read as
  partially met, not met.**
- **Only declared pairings are checked.** A front end is free to combine two
  roles this file does not pair, and nothing would notice. Increment 2 must add
  a check that the shell uses no combination absent from
  `contrastRules.pairings`; until then the harness's coverage is bounded by what
  someone remembered to declare.
- **Non-colour channels are declared but not rendered.** Nothing verifies that a
  component actually draws the icon and label the file promises. That check
  needs a shell.
- **UI-003 and UI-011 are referenced, not established.** The token file carries a
  role for every entity type UI-003 names and every progress state UI-011 names,
  so the vocabulary is in place — but "distinguish visually and textually" is a
  claim about rendered output, and nothing renders yet.
- **The colour-vision floor of delta-E 12 is a judgement, not a standard.** WCAG
  sets no such threshold. It was chosen to be comfortably above the delta-E 10.1
  collapse this increment found and comfortably below the 21.9 the corrected
  palette achieves. A future increment with real user evidence should revisit
  it; it is recorded as chosen rather than derived. It now lives in
  `crates/tokens/src/policy.rs`, so lowering it is a reviewed code change.

## Corrected 2026-07-29 after the project audit

`docs/reviews/PROJECT_AUDIT_2026-07-29.md` demonstrated that two of the claims
this file previously made were not established by the evidence behind them.
Both were fail-open, both are fixed, and both now have mutations:

- **The audited file supplied the thresholds it was audited against.** Lowering
  the `text` floor from 4.5 to 3.0 in `schemas/design-tokens.json` and dimming a
  colour to match let normal-size text pass the entire Tier-1 gate at 3.33:1.
  This was the exact self-consistency failure `AGENTS.md` records for the
  canonical vectors, committed by the harness written to enforce it.
- **The palette owned its own roster.** Deleting `entity.container` from every
  theme, every pairing and the channel table left the gate green at 228 checks
  instead of 234, so a coordinated omission was indistinguishable from a smaller
  product — while UI-003 requires containers to be represented.

Both floors and the full role vocabulary now live in `crates/tokens/src/policy.rs`.
Re-running the audit's own reproductions against the corrected harness produces
3 findings and 2 findings respectively, where both previously produced none.
