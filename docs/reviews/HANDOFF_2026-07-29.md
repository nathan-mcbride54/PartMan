# Handoff notes — 2026-07-29

For the next agent picking up PartMan. This covers what changed today, what I
decided and why, and the things I would want to know before touching this
repository. It is written to be read once, in order.

Read `AGENT_BUILD_SPEC.md` and `AGENTS.md` first regardless. This document does
not restate them and is not normative.

---

## 1. The repository is now public and free software

Three things changed together, and they are connected.

**Licence: `MIT OR Apache-2.0`** (ADR-0006). The project had deliberately
carried no licence, which was defensible while private and untenable on a public
repository — readable by everyone, usable by no one, and every pull request
arriving with undefined rights on both sides.

MIT alone was the original proposal and was rejected: it grants copyright
permissions and is silent on patents, and PartMan drives NTFS, exFAT and APFS
code paths. The MIT arm keeps the result usable by GPL-2.0-only projects
(util-linux, parted are the plausible neighbours), which Apache-2.0 alone would
not. GPL-3.0 was rejected on the grounds that the goal is *users* paying nothing,
not *redistributors* being forbidden to charge — and because copyleft does not
buy the safety guarantee it is sometimes assumed to. A GPL fork can strip
SAFE-007 exactly as a permissive one can. All rejections are recorded in the ADR.

**The licence gate is now real.** `deny.toml` had `private = { ignore = true }`,
which exempted the workspace's own crates from `cargo deny check licenses`. It
is now `false`. This was measured, not assumed: deleting the `license` key from
`partman-domain` fails with `error[unlicensed]`, and declaring
`GPL-3.0-or-later` fails with `error[rejected]`. **Both mutations passed before
the change.**

**A binding constraint you must not break.** ADR-0006 makes the GPL boundary
normative, because a permissive licence only survives contact with the Linux
storage stack if the boundary holds:

- GPL *programs* are invoked as separate processes under SAFE-004. Fine.
- UDisks2 is reached over D-Bus (LIN-001). IPC is not linking. Fine.
- LGPL libraries (`libblkid`, `libblockdev`) may be linked dynamically. Fine.
- **A GPL library MUST NOT be linked, statically or dynamically.**

`libparted` (GPL-3.0-or-later) is named specifically. It is the obvious crate to
reach for when you want a partition-table editor, and linking it would relicense
PartMan by operation of law rather than by decision. **`cargo deny` cannot catch
this** — a `-sys` crate declares its own licence, not that of the C library it
links. It is a review obligation at the integration commit, and there is no
automation behind it. If you are the agent who first needs partition-table
editing on Linux, this paragraph is for you.

## 3. Branch protection is on, and it can bite you

`main` is protected with **11 required status checks**, `strict: true`, and
`enforce_admins: true`. There are 0 required approving reviews, deliberately:
GitHub forbids approving your own pull request, so requiring 1 would lock a solo
maintainer out permanently. The same reasoning rules out
`require_code_owner_reviews`, since `CODEOWNERS` names one person.

Two things follow that will cost you time if you do not know them:

1. **`strict: true` means a branch must be up to date with `main` before it can
   merge.** Merging one pull request makes every other one stale, and each needs
   `gh pr update-branch` plus a fresh full CI cycle. Sequence your merges.
2. **The required checks are matched by name.** They are:

   ```
   Tier 1 / {ubuntu-24.04, windows-2025, macos-15}
   Cross-language hash parity / {ubuntu-24.04, windows-2025, macos-15}
   Supply-chain policy / {ubuntu-24.04, windows-2025, macos-15}
   Real-prober acceptance (FS-004)
   Fuzz smoke (Section 11.4)
   ```

   **If you rename a job, split a workflow, or change a matrix entry, you must
   update the required-check list in the same change.** A required check that no
   longer reports leaves every pull request waiting forever on something that
   will never arrive, and the only fix is repository settings. Issue #35 carries
   this warning too, because it proposes exactly that kind of change.

Secret scanning and push protection are enabled.

endian-independent. **Those reasons are comments in `ci.yml`.** Do not widen

## 5. WP-030 increment 1, and the thing you should take from it

`schemas/design-tokens.json` is the single source of truth for the visual
language. `crates/tokens` computes UI-001, UI-007 and UI-008 from it.
`cargo xtask tokens` runs it; it is inside `cargo xtask ci`.

**The file lives in `schemas/` for a specific reason.** When the Tauri front end
arrives it must read *that file*. `AGENTS.md` already records the lesson from the
canonical codec: an implementation checked against a table it also owns proves
only self-consistency. A CSS variable block copied out of the JSON is that
mistake wearing different clothes.

### What the harness caught

The first palette was chosen by eye and looked entirely reasonable. It failed
ten checks. The one worth remembering:

```
severity.reversible against severity.destructive under deuteranopia
  is delta-E 10.1, below the 12 floor
```

PLAN-004 severity 1 is "fully undoable via an emitted reversal plan". Severity 4
is "data is intentionally destroyed". Mint green and salmon red — obviously
different to a colour-sighted reviewer, nearly the same colour to a red-green
colour-blind one. In the **high-contrast theme**, the one a low-vision user is
most likely to select, the same pair measured **4.8**.

The floor was not lowered. The severity ramp now varies in **lightness** as well
as hue, because lightness survives every colour-vision deficiency while the
red-green axis does not. If you add or change a semantic colour, that is the
principle to preserve — and the harness will tell you if you did not.

### What it does not establish

This matters more than what it does, because "the accessibility harness runs" is
exactly the sentence a reader will over-extend. It is printed on every run and
recorded in `docs/work-packages/WP-030.md`:

- **It renders nothing.** UI-008 also requires keyboard-only operation,
  screen-reader semantics, 200% zoom and reduced motion. None are inspected.
  **M0's "accessibility harness runs" criterion is partially met, not met.**
- **Only declared pairings are checked.** A colour combination the front end
  invents is invisible to it. This becomes load-bearing the moment a shell
  exists — increment 2 must add a check that the shell uses no pairing absent
  from `contrastRules.pairings`.
- **The colour-vision check is a model** (Machado 2009) with the crudest delta-E
  formula (CIE76). Passing is not evidence of real-world distinguishability.
  **UI-007's redundant channels are the guarantee**; the simulation catches two
  roles collapsing, which is a design mistake worth failing a build over.
- **The delta-E 12 floor is a judgement, not a standard.** WCAG sets none. It
  sits comfortably above the 10.1 collapse that was found and below the 21.9 the
  corrected palette achieves. Recorded as chosen, not derived.

## 6. House style, learned the hard way

This repository has a consistent and unusually demanding culture. Match it.

- **Compute, do not record.** A number written beside the thing it describes is
  a claim. A number computed from the thing is evidence. The fixture evidence
  layer, the licence gate, and the token harness are all the same idea.
- **Prove the check can fail.** Every gate is paired with a mutation it must
  reject, and the mutation is confirmed by deleting the check and watching the
  table go red. WP-020 found a gate in `generate` that was load-bearing on
  nothing and kept 74 tests green when removed. I ran the same sweep on three
  token checks before proposing them.
- **Anchor outside the repository.** WCAG's published 21:1; CIELAB lightness
  running 0..=100; `libblkid` 2.41's actual output. A test checked against a
  figure the same code emitted proves only determinism. Where digits cannot be
  trusted (the colour-vision matrices), assert the *defining qualitative
  property* instead.
- **Record what you did not do.** Every document here has a "known gaps" section
  and they are honest. A milestone that exits on a criterion nobody verified is
  worse than one that exits late. Do not round a partial up.
- **Never weaken a threshold to make something pass.** Change the thing.
- **File conflicts, do not guess.** Section 0.2: stop, file a spec issue, do not
  silently pick a side. `docs/spec-issues/` is where they go.
- Commit messages are imperative sentences describing the change's *effect*, not
  `feat:` prefixes. Merged branches are kept, not deleted.

## 8. Things that will mislead you if nobody says them

- **The README's status section is accurate and unusually blunt.** "Not a usable
  partition manager, and must not be represented as one." Nothing here
  discovers, plans, or mutates storage. There is no GUI, no CLI, no planner, no
  privileged helper. A repository with 160 passing tests, three-OS CI, fuzzing,
  supply-chain gates and an accessibility harness can look far more complete
  than it is. It is a very well-built foundation with no product on top yet.
- **`cargo xtask ci` is the local gate and it is not the whole gate.**
  `cross-language` needs Node, `probe` needs Linux, `fuzz` needs the pinned
  nightly, `supply-chain` needs two separately installed pinned tools. Each has
  its own CI job precisely so it cannot be silently skipped.
- **Do not add `[build] rustflags` to `.cargo/config.toml`.** It escapes the
  workspace and applies to every crate compiled anywhere in the repository,
  including `cargo install` builds of the supply-chain tools. This was removed
  once already; the reasoning is in `docs/quality/dependency-policy.md`.
- **`tests/generated/` is gitignored and must stay that way.** Section 16 forbids
  committing binary disk images; they are regenerated by `cargo xtask fixtures`
  and are byte-identical across machines by construction.
- **The mdraid 1.2 fixture is version-keyed, not relaxed.** On util-linux 2.39.3
  `blkid -p` reports nothing for it while `wipefs` still sees the superblock.
  FS-004 Linux RAID and LIN-005 are **not** established on that platform, and
  the reason 2.39.3 rejects it is recorded as unestablished rather than guessed.
  Do not "fix" the expectation table to make it uniform.
