# SI-27 round — 2026-08-09

**Status: a recommendation for Nate's decision, adversarially reviewed.
It decides nothing.** Round three's naming scheme drew nine recorded
defects and a governing finding; this round is built from those
objections, on the foundations fixed since — ADR-0014/0016/0018's
helper-authored architecture and the two requirements ADR-0018 handed
to this round (the theorem premise quantified over edge kinds; edge
semantics classes for the bind set). Untracked session artifact
(`docs/reviews/**`, WP-000).

Deliberately not consumed: SI-37 (given its home by ADR-0018; this
round infers no sameness, per the filing's own instruction), SI-19's
residue (volumes minted inside a container, LVM snapshots), the
multipath path-set encoding (ADR-0011 defers it to the spec change
that first makes multipath writable — this round types the edge and
no more), and SI-28 (untouched).

## 1. The question, and the walls around it

SI-27 asks for a `NodeId`: a **document-local address** — round
three's surviving decomposition, an address is not a device identity —
that is derived rather than stored, stable across re-probes of
unchanged hardware, and whose collision behavior produces an artifact.
The walls:

- **The governing finding**: fail-closed-by-unencodability is not
  fail-closed. A collision that surfaces as an encoder error produces
  nothing to display, journal, or refuse with, and turns a two-device
  ambiguity into denial of discovery for the whole host. Every
  collision below produces a hashable body.
- **The filing's boundary**: when two Weak-identity devices are
  indistinguishable, the snapshot must still exist; the behavior may
  neither *silently* merge the devices nor refuse discovery for the
  host, and any fail-closed limitation attaches to the affected
  targets.
- **Round three's nine defects**, each with a named counter-mechanism
  below: the false collision enumeration (four families, not two); a
  design its own T1/T2 fixtures could not test; a fold not closed
  under the naming relation; member-derived aggregate naming
  (withdrawn); non-injective parent-plus-offset under hybrid tables;
  unnormalized serial text at the recursion root; collision detection
  misplaced in the codec; names depending on other nodes; physical
  block size in the device name.
- **The repairs round four may assume** (Part 6 item 4): a signature
  gains its primary offset; a file system gains kind and superblock
  offset; serial and WWN become bytes under a normative per-platform
  canonicalization; physical block size leaves the naming map; the
  duplicate-designator case sets a flag without re-designating.
- **ADR-0018's handovers**: any new edge kind preserves the
  no-sibling-capture premise or the theorem is re-proved as a property
  test; every edge kind carries a semantics class so the bind set's
  reverse traversal needs no restatement.
- **What changed since round three**: the bound snapshot is
  helper-produced at validation (ADR-0014/0016), so naming inputs are
  facts the helper's named evidence contract reads — the byte layer's
  parsers and the state layer's named APIs. Client drafts use the
  same rule over their own view and are never hash-bound.

## 2. Recommendation

Nine clauses.

### 2.1 The derivation: kind-discriminated positional addresses from contract-read fields

A `NodeId` is derived, never stored: the recursive pair of the node's
kind discriminant and its per-kind naming fields, one of which is its
parent's id — a positional address rooted at physical devices. The
decoder recomputes every id from the node's own fields and rejects any
edge naming an unknown referent (round three's surviving rule), in the
schema-validation pass — the named sole decode boundary with its own
error type, the same boundary ADR-0018's decode-recompute uses; the
codec stays schema-agnostic (defect 7's placement corrected).

The per-kind naming maps, honoring the exclusion list (connection
path, OS instance id, positional indices, table state and checksum,
length, regenerable identifiers, partition type, adapter-formatted
text — all still excluded, plus both sector sizes, physical block size
having already been evicted by repair):

| Kind | Naming fields |
| --- | --- |
| Physical device | canonicalized serial bytes, canonicalized WWN bytes, total bytes — nothing else; vendor/model excluded as transport-influenced text |
| Partition table | parent device id, table role discriminant |
| Partition | parent **table** id, start offset (re-parented onto the table, per round three item 5) |
| Backing signature | host id, family, primary signature offset (the repair) |
| File system | host id, kind, primary superblock offset (the repair; invariant under `btrfs device add`) |
| Encryption layer | its backing signature's id |
| Aggregate | technology, canonicalized native designator bytes (the precondition-2 table) |
| Volume / produced virtual device | producer id, the technology's own volume name and role bytes — never a volume UUID, which is regenerable and excluded; same-name-same-producer duplicates (legal in APFS) fall to the collision group like any equal address |
| File / byte range (new, 2.5) | host file-system id plus canonicalized path bytes, or host id plus range |
| Multipath node | canonicalized platform-reported LUN designator (WWID) bytes |
| Conflicting-entry evidence (new, 2.6) | host table id, view role, entry start offset |
| Collision group (new, 2.3) | the shared name it absorbs |

Created and simulated nodes name positionally from already-named
nodes, as round three established: a created partition from its table
and declared start offset, an initialized table from its parent, a new
file system from its host and declared kind and offset. Captured and
simulated topologies keep their two schema identifiers (domain
separation retained). A moved partition renames — its new address is
its new position, computed in the simulated topology — which is
correct for an address and irrelevant to identity, which SAFE-003's
record carries separately.

### 2.2 The recursion root, canonicalized by source rather than by transformation

Round three's defect 6 was unnormalized serial text at the root. The
repair rides ADR-0018's contract instead of inventing a normalization
algebra: **an identifier used in naming is the byte string returned by
the one named source the evidence contract designates for it, per
platform, verbatim** — no case folding, no prefix stripping, no
re-encoding, non-UTF-8 bytes legal. Choosing the single source is the
normative act (the contract's state layer already names sources), and
it is what makes divergence — round three's "worse than collision" —
structurally absent: two transformations cannot disagree when there is
no transformation and no second source. Where the named source is
`unavailable`, the field is absent, the name is weaker, and any
resulting collision fails closed through 2.3. The per-platform source
designations are versioned with the contract; changing one is a
hash-visible event by construction and lands only with a spec change.

### 2.3 Collision groups: the artifact a collision produces

When two or more same-kind nodes derive equal naming bytes, the body
contains — by domain-layer construction rule, before any encoding —
one **collision group** node carrying the shared name, the observed
count, and an indeterminate marking; the colliding nodes' children
attach under the shared name, recursively subject to the same rule.
The group is the address; no member is individually addressable; every
operand inside the group is `Indeterminate` under ADR-0018's closure —
`blocked`, with the collision as cause and detach-or-disambiguate as
remediation — while detection, display, and diagnostics continue, the
envelope carrying per-OS-node attribution (INV-007) that the body
honestly cannot.

What this is and is not, said plainly:

- **It is not the forbidden merge.** The filing forbids *silent*
  merging. The group preserves two-ness (the count), declares
  indeterminacy, blocks every operand it covers, and attaches the
  limitation to exactly the colliding targets — the whole-host denial
  the governing finding condemns cannot occur, because the body always
  encodes.
- **It is aligned with rules already normative.** Equal stable
  identifiers with no platform-assembled node are already SAFE-005
  ambiguity, `blocked` (Section 2.1, ADR-0011); the measured
  byte-identical L9 pair — every UUID-keyed symlink farm collapsing
  silent-last-writer-wins — is exactly this population. The collision
  group is that ambiguity's *representation*, where the platform's own
  surfaces measured silent.
- **Individually distinct addresses for byte-identical simultaneous
  devices are impossible without an excluded input** — connection
  path, instance id, or arrival order — and every one of those inputs
  is excluded because it renames on replug or churn. This is the
  physics round two and round three each hit from a different side;
  the group is the design that stops pretending otherwise.
- **MODEL-006's duplicate rejection never fires**: the domain layer
  absorbs equal names before encoding, so set encoding is total. A
  fuzz target asserts the whole property: **no on-disk byte sequence
  can make snapshot encoding fail** (Part 6 item 3's demand).

The duplicate-designator case gets the same treatment with the
repaired semantics: two aggregates deriving one designator — a cloned
pool or VG — form a group flagged duplicate, **nothing re-designates**
(defect 8 closed), children keep their addresses because the group
carries the same shared name, operands block with the platform's own
disambiguation as remediation (`vgimportclone` and kin), which is also
the honest FS-008 duplicate-UUID posture.

### 2.4 Property: a node's address depends only on itself and its ancestors

Round three violated this twice and declared neither. Here it is a
stated property with a property test: adding or removing any
non-ancestor node never changes an existing node's address. The
collision group preserves it — each node's *derivation* is
independent; grouping is a construction rule over the observed
multiset whose output address (the shared name) equals what each
member derived alone, so an arriving clone changes a count and a flag,
never an address, and an EIO on one member renames nothing (defect 4's
withdrawal honored: no member-derived naming anywhere — an aggregate
whose native designator is unreadable is `Indeterminate` and not a
plan operand, per precondition 2's recorded consequence, and takes its
place in the body under a designator-absent group name).

### 2.5 The fourth edge kind: host-backing, and the file node

Host-backed virtual devices — loop, dm-linear, plain dm-crypt, VHDX,
attached images — have no on-disk signature and today no legal edge,
which is also why CONC-001's bind set is empty for a loop device. The
new **host-backing** edge (semantics class: "the bytes of A live
within B") runs from a new `File`/byte-range node — a Section 5
addition, named from its host file system plus canonicalized path
bytes, or host node plus range — to the virtual device it backs. Path
bytes in the body are body-stability-clean: a rename is a directory
write, a storage change, and it invalidates dependent plans through
CONC-003 rather than silently re-binding — priced, and the honest
alternative to an inode-shaped regenerable input. The bind set's
reverse traversal picks the edge up by its semantics class with no
restatement — ADR-0018's second handover discharged — so a plan
writing a table to a loop device binds through file to file system to
partition to physical device, and the concurrent-with-imaging hole
closes. This is also what makes the design testable by its own fixture
population — round three's defect 2: equal-size loop devices collided
under the device projection and had no fold, where here each names
from its distinct backing file, so the T1/T2 tiers' four-member
mdraid, two-device Btrfs, and two-store APFS fixtures all address
cleanly.

### 2.6 The table, its views, and conflicting entries

The partition table is one node per device at MODEL-002's chain
position, carrying ADR-0014's helper-authored state, explicit
primary/backup/MBR/EBR extents (ADR-0018's seeds), and a **role
discriminant** for views. Partitions re-parent onto the table, which
restores parent-plus-offset injectivity: the hybrid case's aliased
extent is two entries under two roles — the GPT view's partition and
the hybrid-MBR view's entry — two addresses, no collision (defect 5
closed). Entries that alias or contradict across views materialize as
**conflicting-entry evidence** nodes holding the entries verbatim,
marked indeterminate — INV-008's representation and REC-003's home —
and ADR-0018's closure does the scoping the round-three blanket rule
could not: a step whose affected set reaches conflicting evidence
refuses, steps elsewhere on the same body construct, so "not a
planning base" attaches to the conflicted extents rather than the
whole snapshot. Recovery-scan candidates never enter a captured
topology body at all; they belong to REC-003's preview artifact
(SI-19/WP-R100's schema). The partition type field takes a form able
to carry APM's 32-byte ASCII type string, per round three item 5 —
type remains excluded from naming, so PART-008 renames nothing.

### 2.7 The membership edge, typed — and only typed

ADR-0011's deferred edge is named **platform-membership** (semantics
class: platform-asserted composition; detection-only). It runs from
the multipath node — named from the platform-reported LUN designator —
to its member representation. Members of an assembled multipath node
are represented as a counted member group under the multipath node,
with the kernel's per-path detail in the envelope: individual path
addressing is the path-set encoding ADR-0011 explicitly deferred
behind a MODEL-003 bump to the spec change that first makes multipath
writable, and this round does not preempt it. A member path as a
capability target resolves to the member group: `unsupported` with the
multipath reason, ADR-0011's rule falling out of addressability. The
platform-membership class is closure-inert and bind-inert in v1
(nothing multipath is writable), stated in terms so its later
activation is a decision.

### 2.8 The theorem, re-proved under the extended edge set

The no-sibling-capture premise — no backing or production edge targets
a physical device — extends over the two new kinds: host-backing
targets virtual devices only; platform-membership targets the member
group, is traversed by neither the closure nor the v1 bind set, and
introduces no path from a destroyed range to a sibling physical
device. **The theorem is re-proved as a property test whose topology
generator includes both new edge kinds** — ADR-0018's first handover
discharged as a test, not an argument.

### 2.9 Preconditions 2 through 4, discharged or carried

- **Precondition 2 (native designator table):** the Linux rows exist
  (L7: mdraid array UUID and LUKS2 UUID client-readable; LVM2 VG id
  and ZFS pool GUID helper-only — the indeterminate-aggregate
  consequence instantiated and adopted in 2.4). The Windows rows
  (Storage Spaces pool object id, LDM group GUID) and the macOS APFS
  container UUID row are **owed as evidence obligations**; until each
  exists, aggregates of that technology on that platform derive
  designator-absent names and are `Indeterminate` non-operands —
  fail-closed, nothing blocked from typing.
- **Precondition 3 (`probe_tag` normative):** discharged by
  ADR-0018's byte layer — each parser is fixed by family, offsets,
  magic, and validation, and naming's (family, primary offset) fields
  are read from that same contract. No separate probe_tag artifact
  exists to drift.
- **Precondition 4 (preserved-unknown budgets):** carried into the
  resolution's schema rules: depth capped at a small constant (4),
  size capped at 32 KiB (two LUKS2 16-KiB copies, the recorded
  floor-setter), the over-cap outcome normative — truncation recorded
  as truncation with original length and digest, so INV-008 stays
  auditable — and the SAFE-006 redaction rule versioned so a redaction
  change is a visible body-hash event.

## 3. The adversarial round

**Attack 1 — "the filing says 'without merging them'; a counted group
is a merge with paperwork."** The round's central attack, and the
recommendation stakes its deviation openly: the filing's own qualifier
is *silently*, twice, and the group is not silent — two-ness is
preserved in the count, indeterminacy is declared, every covered
operand blocks, and the limitation attaches to exactly the colliding
targets. The alternative the objection implies — distinct addresses
for byte-identical simultaneous devices — requires connection path,
instance id, or arrival order, each excluded because it renames on
replug or churn, which is the wall both prior rounds died on. What is
genuinely lost is body-level attribution of children to members when
contents diverge below equal device names; the envelope carries that
attribution for display, and no covered node is an operand, so the
loss is visible, never load-bearing. **This is the round's decision
for Nate**: accept the group as the collision artifact, or reject and
the round returns to a wall with no third option on record.

**Attack 2 — "a crafted device with a spoofed equal serial collides
the user's real disk into a blocked group: a denial-of-service
shape."** Sustained as a described property, defended as correct: a
device presenting identity bytes equal to the boot disk's is exactly
the ambiguity SEC-002 and SAFE-005 exist to refuse, the blocking is
pairwise (the host's other devices are untouched — the governing
finding's whole-host failure cannot occur), detection and display
continue, and the remediation is physical (detach). The alternative —
letting either member stay an operand — is the wrong-device write the
product exists to prevent.

**Attack 3 — "path bytes in the body: a rename invalidates plans, and
bind mounts, overlays, and namespaces can make the reported backing
path ambiguous."** Partially sustained. The rename cost is priced in
2.5 and is the fail-closed direction (CONC-003 invalidation, never
silent re-binding). The ambiguity half is an unmeasured platform claim
— exactly the class that sank rounds two and three — so the
loop/VHDX/image backing-designator rows (which API, what bytes,
double-capture stability, behavior under rename and re-attach) are
named evidence obligations, and until a platform's row exists, a
host-backed virtual device on that platform derives a
designator-absent name and its mutating capability is `Indeterminate`.

**Attack 4 — "serial-less devices now collide by size alone: two
different-model 32 GB sticks with no serials block each other, where
SAFE-003's weak path would have allowed confirmed writes."** Sustained
as a priced narrowing, defended on SI-28's own record: for
simultaneously attached indistinguishable-by-record devices, UI-009's
typed confirmation displays the same name for both — Part 7's finding
that the confirmation is no discriminator — so permitting the write
was safety theater. Vendor/model could thin the collision population
but re-enters transport-influenced text (a bridge reports its own
strings), which is defect-6 territory; excluded deliberately, cost
accepted. Single-attached serial-less devices — the common case — are
unaffected.

**Attack 5 — "the group's absorption rule makes the body a function
of the observed multiset; is encoding still deterministic and the
address property still true?"** Refuted by construction: derivation
is per-node over its own fields and ancestors; absorption is a
deterministic function of the derived multiset; the group's address
equals what each member derived alone, so no address anywhere changes
when a colliding member arrives — count and flag change, which is
content, not addressing. The property test in 2.4 pins it.

**Attack 6 — "re-parenting partitions onto the table breaks
ADR-0018's closure statements, which seed 'the table node's extents'
and descend by device-hosted ranges."** Refuted by reading:
ADR-0018 already treats the table as a node with explicit extents and
seeds table writes at it; re-parenting makes the address chain match
the chain MODEL-002 already states (device → table → partition) and
changes no range arithmetic, which is host-qualified by containment
root, not by parent pointer.

**Attack 7 — "two LUKS2 header copies, ZFS's four labels, mdraid's
end-and-head family variants: one consumer, several signature nodes —
does the naming map or the consumer edge collapse?"** Refuted:
signature nodes are named (host, family, offset), so plural copies
are plural nodes with distinct addresses and one consumer under
MODEL-002's unbounded in-degree; the enumerating byte layer reports
all of them by contract. The stale-pair fixture is the committed
regression: ext4 at `0x438` and mdraid 0.90 end-anchored are two
addresses on one host, which is what round three's device-projection
fold could never represent.

**Attack 8 — "naming needs the helper's contract, but the client
draws drafts unprivileged — with what names?"** Refuted by the
architecture already decided: the same derivation runs over whatever a
view holds; a client view missing helper-only fields (a VG id, table
roles) derives weaker names with more designator-absent groups, and
client drafts are unhashed, unbound hints (ADR-0014) — the bound body
is helper-authored at validation, where the contract's fields exist.
Draft-to-validated address movement is expected and harmless: the
plan the user authorizes is the validated one, per ADR-0016.

**Attack 9 — "defer the file node to SI-19 or WP-R100; Section 5
additions are scope creep."** Rejected: without the file node and
host-backing edge, CONC-001's bind set stays empty for the T1/T2
fixture population — the tiers the product tests on — and round
three's record already named the addition as required, with ADR-0018
handing over the semantics-class slot it fills. Deferring it re-opens
the concurrent-imaging hole increment 3 would then freeze into the
first types.

## 4. What this round does not do

- It does not decide the multipath path-set encoding (deferred by
  ADR-0011 to the spec change that first makes multipath writable),
  SI-19's created-node residue, or anything about SI-28.
- It infers no cross-path or cross-device sameness anywhere: groups
  represent indistinguishability, never assert identity.
- It demonstrates nothing end to end: property tests, the fuzz
  target, and the theorem re-proof land with increment 3's types.
