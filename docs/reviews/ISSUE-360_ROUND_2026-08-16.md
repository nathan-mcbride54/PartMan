## 2. The design

**Destruction carries.** The closure gains a destroyed class proper,
distinct from reach: seeded by the target when the step's own destroyed
ranges reach it (ADR-0043's trigger, unchanged), carried along the same
four arms under the same `descends_into` bound as reach, and releasing
— by `NamingFields::released_by_table`, the roster — what each destroyed
node's name describes. A released partition is destroyed in turn. The
row `("volume", "partition-table")` is added to `Containment`.

Three findings shaped it:

*Finding 1 — ADR-0039 had merged the destroyed class into reach.*
`cascade_destroyed` after ADR-0039 is "reached by descent from any
member of the set", which is why a table on a volume reached by
`Wipe(member)` did not release, and why "any reached table releases"
is wrong: `Label(member)` reaches the same table. The act re-separates
the two — `destroyed ⊆ cascade_destroyed`, carried only from destroyed
sources — without touching reach.

*Finding 2 — the seed must be the target and only the target.* Seeding
from every range-destroyed node re-derives round 2's L1: `Wipe(bios_grub)`
touches the table's conventional extent, and a table so touched would
release every sibling. Mutation M3 confirms it: four guards die.
Range-destroyed non-target nodes keep exactly HEAD's behaviour — reached,
descending — and establish no destruction of their own.

*Finding 3 — the modelling is one row.* The array's block device is the
produced volume; the table's `parent` names it; `aggregate → volume →
table → partition`. No `aggregate → partition-table` row; the pair is
asserted refused. `multipath-node` rows are not added and not decided
(ADR-0011). The pair is geometric in kind and never compared, since a
volume declares no extent — ADR-0041's revisit condition, discharged by
reading.

## 5. The named limit, and the candidate held

`Wipe(md0)`: an extentless target's canonical destroyed entry is empty,
so the target is never in `range_destroyed` and destruction is never
seeded; the table it carries is reached as content, `md0p1` and the pool
are not. Pinned as a committed row in
`destruction_carries_only_from_the_target_and_reach_never_releases`.

The candidate — `canonical_ranges` gives an extentless target of `Wipe`,
`Encrypt`, `Move`, `Shrink` the entry `HostRange { host: target, start:
0, length: u64::MAX }` — was applied and the workspace run: **669 tests,
1 failed, the failure being the pinned limit row itself** (`Shrink(md0)`
→ `Unsupported{InheritedFromConsumerOrProducer}`); every planner and
capability test green. Reverted. Held and filed as **#392**, because it
moves `canonical_ranges` (two consumers) and the planner's
`destroyed_closure` on `Wipe(volume)` — a population no planner test
exercises — which is the uncovered-clause shape this issue's own history
refuses. `Wipe(array)` stays `Clear` even under the candidate (nothing is
framed on an aggregate), which is worth knowing before that act.

## 6. Rejected

Two rows (`aggregate → partition-table` beside the volume row): two
spellings for one layout; rejected, the pair asserted refused. The row
alone: known-broken protection, ADR-0043's own measurement; rejected.
Release on reach (M2), seed from every range-destroyed node (M3),
released partitions merely reached (M4): all killed. Landing #354's kind
half here: the multipath population is still admitted by no row and
ADR-0011's intent is not examined; not taken. The whole-frame candidate:
held, §5.

## 7. Not established

- A panel verdict. The claims most worth attacking: (a) that seeding from
  the target alone is the right — and complete — trigger, given a
  device-target step with a *partial* destroyed range now releases every
  partition on the device (nothing delivered emits it; stated in the ADR
  as ADR-0043's priced limit one level up); (b) that carrying destruction
  across the backing arm from a destroyed member signature is right for a
  redundant array (it is what ADR-0018's rule 4 already did for reach, and
  it is fail-closed); (c) that M6's single kill is enough coverage for the
  bound on destruction, given the bound is structurally the same `if` as
  reach's.
- Whether the `multipath-node` rows are ADR-0011's intent — #354's.
- Anything about #392 beyond §5.
- The observation, made in passing and not this act's: `device_scope_verdict`
  ascends containment roots only, so content on a produced volume (a
  file system on `/dev/mapper/x`) does not inherit the underlying disk's
  device-scope verdict — a remote-transport disk under LUKS gives its
  mapped file system `Permitted` on that arm. Pre-existing; not filed
  here because it was not measured beyond reading the code.
