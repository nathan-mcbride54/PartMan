## Zero-loss check

The generated document is deliberately narrower than the former narrative: it
is an evidence relation, not a status report. Status, historical corrections,
negative claims, measured margins, and future rendered-accessibility work stay
in `docs/work-packages/WP-030.md`. Test-to-requirement relationships now live
beside compiled Rust tests, while path and command relationships live in the
typed evidence block.

`cargo xtask traceability` validates generated output byte-for-byte, test names
against compiled libtest output, paths against Git and WP-030 ownership,
commands against the real xtask parser, and requirements against
`AGENT_BUILD_SPEC.md`. Semantic adequacy remains a review obligation and is not
misrepresented as mechanically proven.
