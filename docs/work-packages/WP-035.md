# WP-035: Read-only CLI chassis and evidence instrument

- Spec version: 4.2.0
- Stage: Evidence (M0.5)
- Objective: Build `partman inspect` — the unprivileged, read-only, offline,
  cross-platform instrument that answers what a machine exposes and whether
  PartMan's dependencies are usable there — and take two named register
  measurements: SI-33's media-change-counter liveness experiment and SI-35's
  loop-device and Windows partition-list measurements. The chassis requires no
  decision from any register item gating WP-010 increment 3, and it is
  forbidden every surface those items gate. It answers with per-field
  provenance — which interface reported which value — and never synthesizes a
  verdict from what it observed.
- Requirement IDs: SAFE-004, SAFE-005 (fail-closed refusal posture only; no
  write operation exists here to disable), SAFE-006, SEC-007, MODEL-003
  (schema versions on this package's own JSON surfaces; the domain-payload
  regime remains WP-010's), MODEL-004 (precursor observation records only:
  adapter, version, method, and ADR-C4's outcome vocabulary as the ADR wrote
  it — observed, with absence as a value; unavailable; failed — the hashed
  envelope these eventually live in is WP-010's to deliver), CLI-002
  (export-diagnostics only), CLI-005 (documented; provisional within major
  version 0), CLI-008, INV-006, INV-007, CAP-004, FS-007 (inputs only:
  static technology-limit facts; the blocked-reason capability surface is
  WP-050's)
- Prerequisites: WP-000, WP-020, repository issue #94 for anything loop-backed
- Test tier: T1, unprivileged. No test opens a block device, and no test
  launches a roster tool: the doctor's I/O goes through an injected launcher
  seam, so the tier's process set stays `git` and the compile-time-selected
  `cargo`, and the one test of the real launcher probes that same `cargo`.
  The SI-33/SI-35 measurements are operator-run, read-only experiments
  recorded in `docs/quality/observability.md` — the SI-28
  hardware-confirmation precedent — not tests and not repository commands;
  the loop-backed portion is additionally gated on repository issue #94
  (nothing binds `/dev/loopN` to a verified handle until that closes).
- Acceptance scenarios: none directly assigned. ACC-009 (missing tool) depends
  on CAP-004 work delivered here but is not claimed by it.

CLI-004, CLI-006, and CLI-007 are deliberately **not** claimed: the chassis has
no mutation argument surface, no secret consumer, and no plan to dry-run, so
each would be satisfied only vacuously. The structure preserves their posture —
there is nothing to bolt `--force` onto — and the requirements stay claimable
by the packages that can evidence them non-vacuously (WP-080, WP-085).

## Boundary — surfaces this package must not build

Each is blocked by a named open register item, and the refusal is the feature:
every gated surface refuses with a typed value carrying the gating issue —
`{"strength": {"state": "not-established", "gate": "SI-28"}}` — never merely an
exit code or a stderr string, and never a silent omission.

- **No `IdentityStrength`** — SI-28, SI-35. Recording what a device reported is
  not asserting what the identifier identifies, and that attribution question
  is what SI-28 leaves open. The inspector prints raw identifier strings, each
  labelled with the interface that produced it, and never prints a strength.
- **No ADR-C3 partition-table state, no table checksum** — SI-35.
- **No typed Section 5 node, no `TopologySnapshot`, no artifact hash, no
  plan** — SI-27, SI-34, SI-35. Two mechanical guards enforce this, and their
  exact reach is stated so the sentence cannot rot into an overclaim: the
  shipped dependency closure is empty (asserted through `cargo metadata`, so
  no hash or plan implementation can arrive from outside the crate), and the
  output type carries a compile-fail proof that it does not implement `Hash`.
  What neither guard can see — `std`'s own hashers used deliberately
  in-crate — is a named review obligation. Increment 1 is not complete until
  both guards exist and defeating either fails the suite.
- **No stable device handle** — SI-27. (Formerly "via SI-12's multipath
  question"; SI-12 resolved in spec 4.3.0, and the handle gate is SI-27's
  alone now.) Selectors are session-local indexes or the platform's own path,
  documented as unstable across runs. This is a real product cost and it is
  the cost of not guessing.
- **No claim that two paths are or are not the same device** — a standing
  decision now, not an open question: ADR-0011 (spec 4.3.0) made
  no-cross-path-sameness-inference the product rule. The prohibition is
  unchanged; its authority moved.
- **No protection verdict** for ZFS, Storage Spaces, LDM, Fusion, or Apple
  sealed system — SI-11 (inputs SI-29, SI-30). The Section 2.1 verdicts
  themselves are decided; what SI-11 holds open is the enforcement mechanism,
  and this package builds neither.
- **No per-target capability verdict, and no CAP-003 status values.** The
  status vocabulary and its reason enum belong to WP-050's capability engine;
  the register's round-three record fixes the closed reason enum as the home
  for gated-state reporting. Technology-limit facts (FS-007 inputs) are in
  scope; a verdict about a target is not.
- **No `plan`, `validate`, `dry-run`, `apply-plan`, `status`, `resume`,
  `cancel`** — there is no honest partial `plan`.
- **No unversioned JSON, and no domain payloads.** Every JSON surface this
  package emits — refusal values, progress events, doctor and diagnostics
  envelopes — carries a schema version this package owns, documented as
  provisional within major version 0 (MODEL-003). Inventory, topology, and
  capability payloads are absent from output entirely; a request for them
  refuses with a typed value naming the gate. CLI-001's stable-JSON obligation
  stays with the packages that own those surfaces.

A read-only inspector satisfies SI-28's interim conservative floor vacuously.
The inspector's vacuous compliance may not be cited toward narrowing that
floor; the SI-33 measurements increment 5 takes are register evidence and are
cited there, not here.

## Increments

1. **Chassis.** `apps/cli` workspace member (`[lints] workspace = true`,
   `unsafe_code` denied by inheritance, `//!` docs). SAFE-004 structured argv —
   no shell strings anywhere, and the non-Unicode-argument seam owned as a
   typed refusal rather than left to `std::env::args()`'s panic. CLI-005
   exit-code contract, documented and explicitly provisional within major
   version 0, its literal values pinned by test. ANSI-free `--json` with a
   schema-versioned envelope for every surface this package owns. `NO_COLOR`
   is honored by construction — no colour exists to disable — and non-TTY
   detection arrives with the first colour, not before; JSON Lines progress
   events arrive with the first long-running surface, not before. Both
   triggers are named here so the vacuous state cannot be read as delivered
   machinery. The typed-refusal vocabulary carrying gate identifiers — the
   first real feature, and the model for every later gated surface. Converts
   the traceability mode to `generated`. Adds the two structural guards named
   in the Boundary.
2. **Redaction and diagnostics.** Deny-by-default redaction as an allowlist
   (SAFE-006, INV-007) — an allowlist need not know what the denied fields are,
   so it is model-independent. SEC-006's field list (device serials, paths,
   labels, usernames, keys, file names) is adopted as the deny-floor; no
   telemetry exists or is added. Redacted `export-diagnostics` (CLI-002,
   INV-007). Redaction tests gate the tier: a raw value in output fails it.
3. **Doctor and facts.** Dependency doctor (CAP-004): tool present, version,
   in/out of tested range, resolved from trusted absolute paths only (SAFE-004,
   Section 16 — no PATH search, no parsing of human-localized output where
   structured output exists). Technology-limit facts (FS-007 inputs only):
   properties of a technology, never a verdict about a target, with no CAP-003
   status attached.
4. **Observation records.** Adapter-attributed observation records — toward
   MODEL-004, whose envelope residence is WP-010's to deliver: what each
   interface returned, tagged with source adapter, version, method, outcome.
   Positively observed absence is a value; unavailability is not (ADR-C4).
   Exercised by fixture-backed replay over WP-020's deterministic images at
   Tier 1, with no device access.
5. **Register measurement instruments.** Protocols and recording formats for
   the SI-33 media-change-counter liveness experiment and the SI-35
   loop-device / Windows partition-list measurements, executed as operator-run,
   read-only experiments whose results land in
   `docs/quality/observability.md`. Anything loop-backed is blocked until
   repository issue #94 closes; if a read-only measurement is ever taken before
   then, the gap is recorded beside the numbers.

## Verification

Every increment: `cargo xtask ci`, `cargo xtask test --tier 1`,
`cargo xtask verify-change-ownership --base origin/main`. Increment 1 adds the
structural guard tests and the traceability conversion; increment 2 adds the
redaction tests to the tier; increment 4 adds replay determinism. No
requirement is recorded as delivered without a generated traceability row
backed by a live test.
