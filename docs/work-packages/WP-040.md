# WP-040: RPC schemas, transport per OS, handshake, helper authentication skeleton, redaction

- Spec version: 11.2.0
- Stage: Foundations (M0)
- Objective: Deliver the client/helper protocol layer RPC-001 through
  RPC-006 charter: the versioned message schemas and their strict
  both-directions validation posture, the handshake with its
  refuse-never-degrade version rule, bounded sizes and the
  request/response-versus-events stream separation with resynchronizable
  sequence numbering, the deny-by-default redaction boundary, and the
  helper-authentication skeleton as a closed vocabulary of per-OS
  verification claims — all as a pure library over the canonical
  encoding WP-010 already proves cross-language. The per-OS transports
  themselves are **route-decision-gated**: no transport is
  simultaneously dependency-free, `unsafe`-free, and clean against the
  workspace rules (the WP-035 increment-10 triangle, three times over),
  so each opens only after a recorded choice among its named routes,
  never by drift.
- Requirement IDs: RPC-002, RPC-003, RPC-004, RPC-005 (typed operations
  only; no dynamic code, no path-addressed execution, no raw
  passthrough — held structurally by the protocol carrying only
  `schemas/`-defined types), RPC-001 (claimed, increment-gated: each
  OS transport behind its own recorded route decision), RPC-006 (the
  protocol half: resume tokens and event sequence numbers; the journal
  a client reconstructs from is WP-070's, and reattach *behavior* binds
  when both exist), SEC-007 (the transport is local IPC only; nothing
  here opens a network socket), MODEL-003 (schema versions on every
  message format this package owns), SAFE-009 (workspace lint
  inheritance). Consumed, not claimed: MODEL-005's canonical encoding
  and its cross-language proof (the wire body encoding is `pce/1`,
  WP-010's, so both sides of the RPC boundary already hash and encode
  identically), SEC-006's redaction floor (the field classes are the
  spec's; this package applies them at its boundary), and HLP-*
  behavior (the helper is WP-070's; this package defines what a helper
  must present, never what it does).
- Prerequisites: WP-000, WP-010 (increments 1–2: the codec and its
  cross-language harness)
- Test tier: T1, unprivileged. The protocol layer is pure: no test
  opens a socket, pipe, or XPC connection, launches a process, or
  reads the environment. Transport increments, when their routes are
  decided, state their own test posture in the route decision — an
  IPC endpoint cannot be tested without creating one, and what Tier-1
  may create is part of what each route decision must record.
- Register gates: **none open.** SI-18 — the gate this row named,
  whether a severity-1 plan needs fresh interactive authorization —
  resolved 2026-08-11 in spec 11.2.0 by ADR-0021: authorization is a
  two-tier ladder (a floor act for every apply at every severity; the
  interactive ceremony at severity ≥ Disruptive or any step flag), the
  enforced tier derives from the helper's own recomputed severity and
  flags (HLP-002), and **no authorization-requirement field enters the
  plan** — the requirement is a total function of body content the plan
  already carries, so the jointly-sequenced WP-010 schema change this
  gate once anticipated does not arise. The authentication skeleton's
  identity-only vocabulary is therefore a standing decision rather than
  an interim posture: identity claims name what a peer proves it is,
  the helper-computed tier arrives as validate-plan response data with
  WP-070 (HLP-003, ADR-0021), and nothing a client sends can assert it
  (CAP-007).
- Milestone sequencing, recorded so the start is honest: M0 remains in
  progress on the README's criteria table (three partial rows).
  Milestones gate integration exit, not package start (the
  WP-035/WP-050/WP-060 precedents under the same sequential rule), and
  nothing here integrates a surface: no helper exists to connect to,
  and the first real endpoint arrives with a transport route decision.
  Starting this package asserts no milestone exit.

HLP-*, JRN-*, CLI-*, and UI-* requirements are deliberately not claimed:
this package defines the protocol both ends speak, not the helper that
answers (WP-070), the journal that persists (WP-070), or the surfaces
that render (WP-080/WP-030). CAP-007's advisory rule shapes the schema
design — nothing a client sends can assert a capability, a verdict, or
an authorization — but the requirement stays with the packages that
compute those values.

## Boundary — surfaces this package must not build

Each prohibition names its governing authority.

- **No transport without a recorded route.** RPC-001's three transports
  each need platform reach the workspace forbids by default: Windows
  SDDL-restricted named pipes need Win32 security APIs, Linux
  peer-credential verification needs `SO_PEERCRED` beyond std's
  surface (**recorded 2026-08-19: ADR-0055, route T1 — `std` plus
  `rustix`'s safe `socket_peercred`; increment 5**), and macOS XPC or its
  verified-socket equivalent needs platform frameworks. No route is simultaneously dependency-free,
  `unsafe`-free, and clean against the workspace rules — the WP-035
  increment-10 triangle, and that precedent's discipline holds: each
  transport increment opens only after a recorded choice among its
  named routes, with the route's dependency, `unsafe`, review, and
  Tier-1-testability costs stated and accepted in review. Until then
  the protocol layer is complete and endpoint-less, and that is a
  truthful state, not a gap.
- **No authorization semantics.** A standing decision now, not an open
  gate: ADR-0021 resolved SI-18 (spec 11.2.0) with no plan-carried
  authorization-requirement field — the tier is the helper's own
  computation from its recomputed severity and flags, and a
  client-assertable authorization stays unrepresentable (CAP-007). The
  authentication skeleton names identity claims (what a peer proves it
  is), never authorization rules (what a peer may do, or when a human
  must re-approve); HLP-003's two-tier binding is WP-070's to implement
  under ADR-0021, with the computed tier carried as validate-plan
  response data, never asserted through any message a client authors.
- **No helper behavior, no journal.** The protocol defines message
  shapes for validation, execution, progress, and reattach; the helper
  that validates and executes is WP-070's, and RPC-006's
  reconstruct-from-journal behavior binds when the journal exists.
  This package ships sequence numbers and resume tokens — the
  protocol's half — and nothing that pretends to replay.
- **No raw passthrough, structurally.** RPC-005 is held by construction:
  message bodies are `pce/1`-encoded values of `schemas/`-defined
  types, decoded through strict validation that rejects unknown fields
  and out-of-range values in both directions (RPC-003, with the helper
  side strict and the client side equally strict here — one library
  serves both ends, so laxness has nowhere to live). No message carries
  a path to execute, a command string, or dynamic code.
- **No network reach, ever.** SEC-007 at this layer: the transports are
  local IPC. Nothing in this package's shipped code may open, listen
  on, or connect to a network socket, and the schema vocabulary
  contains no network address type to smuggle one through.

## Increments

1. **The message layer.** `crates/rpc` workspace member (workspace
   lints, `unsafe_code` denied by inheritance), depending on
   `partman-domain` for the canonical codec. The versioned message
   envelope (MODEL-003 schema identity and version, `pce/1` body,
   RPC-004's size bound as a schema constant checked at decode), the
   handshake exchange (RPC-002: schema and build versions both ways,
   with the compatibility rule as a total function — compatible, or a
   typed refusal carrying a remediation message, never a silent
   degrade), and the strict decode posture (RPC-003: unknown fields
   and out-of-range values reject, both directions, one validator for
   both ends). `schemas/rpc/envelope.md` and
   `schemas/rpc/handshake.md` document the formats in the
   `schemas/domain` shape. Converts the traceability mode.
2. **Streams and reattach vocabulary.** RPC-004's second half: the
   request/response channel and the event stream as distinct message
   classes, events loss-tolerant by design — monotone sequence
   numbers, a resume token type, and the resynchronization rule stated
   in the schema doc (a client that misses events re-anchors from its
   last sequence number; what it re-anchors *against* is the journal,
   WP-070's, and the doc says so). Timeout vocabulary as typed
   configuration the consumer supplies — this pure layer has no clock,
   exactly like the planner.
3. **The redaction boundary.** SEC-006's deny-floor applied at the
   protocol edge: a schema-level rule for which envelope and event
   fields may carry identifier-class bytes at all, held the WP-035
   way — an allowlist that need not know what the denied fields are —
   with a test that a raw serial, path, label, username, or key
   appearing in any non-allowlisted position fails the suite.
4. **The authentication skeleton and the record.** The closed
   per-transport claim vocabulary RPC-001 implies — the SDDL identity
   a Windows pipe must restrict to, the peer credentials a Unix socket
   must verify, the code-signing requirement a macOS connection must
   check — as **types naming what a peer proves, verified by nobody
   here**: each claim's verifier arrives with its transport's route
   decision, and the skeleton's doc says which claim waits on which
   route. No authorization vocabulary (SI-18's gate, stated in the
   types' docs). Package record sweep: README row, CHANGELOG,
   generated traceability current.

5. **The Linux transport (opened 2026-08-19 by ADR-0055, spec 19.0.0, on
   the Linux transport route round).** `crates/transport-linux`
   (`partman-transport-linux`): the endpoint — a root-owned directory
   searchable but not writable by others (`0711`), checked fail-closed
   (owner is the endpoint's own euid, mode exact, no pre-existing
   non-socket or symlinked node, never a mode change on a path it did
   not create); the socket node owned by the authorizing user and `0600`;
   on accept, the peer's credentials read through `rustix`'s safe
   `socket_peercred` and the connection **refused before any byte is
   read** unless the `uid` is the endpoint's authorizing user (HLP-007,
   `IdentityClaim::UnixPeerCredentials`'s verifier); then RPC-002's
   handshake and RPC-004's bounds and timeouts over a length-prefixed
   frame, both ends in one crate. The client side connects and runs the
   same handshake. Tier-1 as ADR-0055 decision 6 states: a listener under
   a temp directory the test owns, a `pair` whose credentials are the
   test's own, the refusal arm through the verifier's seam; the
   root-owned directory, the foreign uid and the cross-user connect are
   a Tier-2 acceptance in a disposable guest, recorded with the
   increment. `IdentityClaim::UnixPeerCredentials::waits_on` flips to name
   ADR-0055 and this increment. Package record sweep.

Beyond these five: the Windows and macOS transport increments, each
opening only after its recorded route decision (the increment-10 shape),
with the route's costs stated and its Tier-1 test posture part of the
record.
SI-18's resolution (ADR-0021, spec 11.2.0) unlocked no schema work at
all: the answer is that no authorization-requirement field exists — the
tier is helper-derived from the plan body's severity and flags — so the
jointly-sequenced WP-010 schema change this paragraph once anticipated
does not arise, and the helper-computed tier arrives as validate-plan
response data with WP-070.

## Verification

Every increment: `cargo xtask ci`, `cargo xtask test --tier 1`,
`cargo xtask verify-change-ownership --base origin/main`, real exit
codes checked. Increment 1 adds the strict-decode suite and converts
traceability; increment 2 adds the sequence/resync vocabulary tests;
increment 3 adds the redaction gate to the tier — a raw value in a
non-allowlisted position fails it; increment 4 adds the
claim-vocabulary closure test. No requirement is recorded as delivered
without a generated traceability row backed by a live test.
