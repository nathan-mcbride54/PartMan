# WP-010: Canonical domain model and encoding

- Spec version: 3.1.0
- Objective: Define the canonical domain model, schema versioning, and the
  canonical encoding and hashing required by MODEL-005.
- Requirement IDs: MODEL-001, MODEL-002, MODEL-003, MODEL-004, MODEL-005
- Prerequisites: WP-000, and ADR-C1 accepted (Section 15)
- Test tier: T1, unprivileged
- Acceptance scenarios: None directly assigned

## Owned paths

- `crates/domain/`
- `schemas/`
- `docs/traceability/WP-010.md`
- `docs/work-packages/WP-010.md`

## Delivery status

This package is being delivered in increments. Each is independently gated.

| Increment | Scope | Status |
| --- | --- | --- |
| 1 | `pce/1` canonical encoding profile, Rust codec, golden vectors, strict decoder | Delivered |
| 2 | TypeScript codec and cross-language golden-test harness (MODEL-005) | Delivered |
| 3 | Section 5 domain types with MODEL-003 schema versioning and MODEL-004 provenance | Not started |
| 4 | `cargo-fuzz` target for the decoder (Section 11.4) | Not started |

Increment 1 is the part ADR-C1 gates, and everything else in the package
encodes through it, which is why it is first.

## Assumptions

- The encoding profile is fixed by ADR-C1 and specified in
  `schemas/canonical-encoding.md`. Changing it is a profile version bump, not an
  edit, because it would change every hash previously issued.
- No field in the Section 5 domain model is inherently floating-point. The
  profile makes floats unrepresentable, so a genuine need for one is a spec
  question before it is an encoding question.
- `usize` is at most 64 bits on every supported target.

## Out of scope

- RPC transport and schemas (WP-040).
- Capability engine interfaces (WP-050).
- Any discovery, planning, or storage mutation.

## Increment 3 is blocked

Increment 3 cannot start. Extracting the Section 5 requirements surfaced
twenty-six specification conflicts, eleven of which must be decided before a
domain type is written; ten of those change canonical bytes. They are filed in
`docs/spec-issues/README.md` as Section 1.11 requires.

Ten of the twenty-six are hash-visible. Under MODEL-005 and ADR-C1 a hashed
artifact's shape cannot be changed later without invalidating every hash the
product has issued, and an authorization token that no longer matches has no
migration path. Choosing now and correcting later is the only option with no
cheap exit, which is why this stops rather than proceeds on assumptions.

Increment 4 (`cargo-fuzz`) does not depend on the domain types and can proceed
independently.
