## Assumptions

- The encoding profile is fixed by ADR-C1 and specified in
  `schemas/canonical-encoding.md`. Changing it is a profile version bump, not an
  edit, because it would change every hash previously issued.
- No field in the Section 5 domain model is inherently floating-point. The
  profile makes floats unrepresentable, so a genuine need for one is a spec
  question before it is an encoding question.
- `usize` is at most 64 bits on every supported target.

## Out of scope

- RPC transport and schemas (WP-040).
- Capability engine interfaces (WP-050).
- Any discovery, planning, or storage mutation.

Increment 3 cannot start. Extracting the Section 5 requirements surfaced

Under MODEL-005 and ADR-C1 a hashed artifact's shape cannot be changed later

## Codec remediation, before any domain artifact uses this encoder

A progress review found two defects on the MODEL-005 authorization boundary and
reproduced both. Neither needed a specification decision, and both had to close
before increment 3 writes a type that hashes through this codec.

### A forged boolean was authenticated as the opposite value

The TypeScript `bool` arm used JavaScript truthiness:

```ts
out.push(value.value ? 0xf5 : 0xf4)
```

so `{ kind: 'bool', value: 'false' }` encoded as `f5` — canonical **`true`** —
and `hash` published a digest over the opposite logical value. Reproduced before
fixing: the forged payload emitted `f5`, and `{ kind: 'bool', value: 0 }` emitted
`f4`.

TypeScript types do not protect an object that arrived as JSON, over RPC, from a
plugin, or as `unknown`. That is exactly why the `text` and `bytes` arms already
validated at runtime — `TextEncoder` coerces a non-string and `Uint8Array.from`
truncates modulo 256 — and the same reasoning simply had not been carried to the
rest. Rust is unaffected: its `match` is exhaustive over a real enum, so the
value cannot be constructed.

Every variant now validates:

- `bool` requires an actual boolean, so neither a truthy nor a falsy non-boolean
  can become either byte;
- `array` requires an `Array` and `map` a `Map`, where previously `.length` and
  `.size` on something else gave `undefined`, `BigInt(undefined)` threw a native
  `TypeError`, and the module's contract that every refusal is a
  `CanonicalError` quietly stopped holding;
- **map keys must be primitive strings.** This was the quietest of them:
  `requireWellFormed` iterates `.length`, which is `undefined` on a number, so
  its loop never ran and the key passed — then `utf8` coerced `1` to `"1"`. A map
  keyed by a forged number encoded as one keyed by text;
- a map key present with no value is refused rather than dereferenced;
- and a `value` that is not an object, or carries no string `kind`, is refused
  before its payload is read at all.

The test that should have caught this covered `text` and `bytes` only. It is now
table-driven with at least one forged payload per variant, so a variant added
without validation fails it, plus a dedicated test asserting a forged boolean is
refused in *both* directions and a property test that everything the encoder
accepts decodes back to the same value.

### Raw-byte hashing proves `pce/1`, not an artifact schema

Both languages exported a function that hashed whatever bytes it was handed,
documented as "use this only for bytes produced by `encode` or accepted by
`decode`". That is an instruction, not a guarantee. HLP-001 applies plans by
hash, HLP-003 binds interactive authorization to an exact hash, and SEC-001
authorizes only exact hashes, so a public digest-over-anything is a bypass for
whoever forgets.

`hash_canonical_bytes` and `hashCanonicalBytes` are gone. `hash_encoded` /
`hashEncoded` take their place and **decode first** — `decode` accepts only the
unique canonical `pce/1` encoding, so bytes that survive it are byte-canonical
by construction rather than by the caller's say-so. The private digest helper
each language keeps is called only where `encode` produced the bytes a line
earlier.

That is deliberately narrower than artifact validity. Generic `pce/1` must
accept a descending Array because it may be a semantic sequence; the same bytes
are invalid when an artifact schema declares that field to be a set. Therefore
the future increment-3 API must expose a typed decode/validate/hash path that
checks every schema invariant, including MODEL-006, before the exact bytes
enter authorization. HLP-001/HLP-003/SEC-001 callers MUST use that typed path
and MUST NOT treat the generic `hash`/`hash_encoded` primitives in either
language as an authorization verdict.

No digest changed: both languages still reproduce every recorded `sha256` in the
shared vector file, and a test in each asserts the two routes to a hash agree.

### What an adversarial pass then found in the fix

The first version of this remediation was attacked before it was proposed, and it
was directionally right and incomplete in a specific way: **every guard checked a
field, and a payload can lie about a field between two reads.**

- **`kind` was read twice** — once by the shape check, once by the dispatch — so
  a getter could be validated as `bool` and written as `null`. Both arms happened
  to be safe, which is why it is worth pinning: the guarantee held by luck.
  `kind` and the payload are now each read exactly once, and a test counts the
  reads.
- **Containers declared a count and then wrote a body**, reading the source
  twice. A `Proxy` over an array reporting `length` 5 while holding 2 items, or a
  `Map` subclass whose `size` disagrees with `entries`, produced a head that did
  not describe the body. Both are now snapshotted into private containers
  through captured intrinsics before anything is measured.
- **`bytes` trusted `Symbol.iterator`.** `instanceof Uint8Array` passed while a
  lying iterator yielded values outside `0..=255`, which `Uint8Array.from` then
  truncated modulo 256. The copy now verifies the exact intrinsic Uint8Array
  brand and copies indexed bytes into a new plain byte array.
- **`instanceof` is not a brand.** `Object.create(Uint8Array.prototype)` passes it
  with no typed-array internals, and the copy above then threw a native
  `TypeError` — breaking the contract that every refusal is a `CanonicalError`.
  Those are now converted.
- **`hashEncoded` validated a prefix and hashed a buffer.** `decode` walks the
  array through its `length` property while `crypto.subtle.digest` reads the
  underlying buffer, so a view with a shadowed `length` got its prefix validated
  and its whole buffer hashed — a digest over bytes nothing proved canonical,
  which is the one thing that function exists to prevent. Both steps now see the
  same snapshot.
- **Species and mutable prototypes could substitute semantic content.**
  `Array.prototype.slice` consulted a caller-controlled constructor species,
  and indexed getters could replace `push`, `map`, or `sort` after the call
  began. A generic Array element was changed, set elements were dropped or
  reordered, and a wider typed-array species made `hashEncoded` validate one
  byte while hashing two. Array/set snapshots are now species-free, internal
  arrays use captured intrinsics, and typed bytes are copied only after an exact
  brand check. Dedicated regressions reproduce each route.

The tests were vacuous in the same way the code was. `every variant refuses a
forged runtime payload` asserted only the error *class*, and its `array` case
used the string `'not an array'` — which has a `.length`, so the encoder walked
it as a sequence and refused one of its characters. **The array guard never ran,
and deleting it left all 24 tests green.** Every case now names the phrase its
refusal must contain, exactly as WP-020's mutation table does.

### Each guard is proven by a deletion that fails the suite

| Guard | Deleting it |
| --- | --- |
| `bool` must be a boolean | caught |
| `array` must be an `Array` | caught |
| `map` must be a `Map` | caught |
| map keys must be strings | caught |
| `hashEncoded` validates the bytes it hashes | caught |
| Array and set snapshots ignore constructor species | caught |
| Set snapshots/sorts use captured intrinsics after caller getters | caught |
| Byte snapshots require an exact Uint8Array brand and ignore species | caught |
| `encode` decodes its own output | **not caught** |

The last row is recorded rather than hidden. `encode` re-decoding its own output
makes §6.1 a computation instead of a claim, but every attack the pass produced
is caught by a field guard first, so **no test currently requires it and it is
not counted as evidence.** It is kept as defence in depth against the variant
nobody has thought of yet — which is exactly the case that cannot be written as a
test — and the code says so where it sits.

Each of the two original fixes was also verified by reverting it and confirming
the new tests fail.

Accepting ADR-C5 and ADR-C6 does **not** unblock this increment. They fix the
aggregation vocabulary and set encoding, respectively; the authoritative issue
register still has unresolved hash-visible and protection-model gates. Writing
types against only some answers would freeze a shape the rest are still free to
change.

SI-28 is the exception to the ordering above: it is a data-destruction path in an
already-accepted decision (ADR-C3) rather than a question about types, and it
does not depend on anything else here.

Increment 4 (`cargo-fuzz`) did not depend on the domain types and is delivered.

## Verification and remaining limits

`cargo xtask ci` runs the Rust codec and stable canonicality suites at Tier 1.
The domain crate performs no I/O, launches no process, and never touches
storage, so this package cannot reach a host or user disk. It neither implements
nor exercises privileged behavior.

`cargo xtask cross-language` runs the Rust and TypeScript suites against the
same canonical value and canonical-set fixtures. The command remains a separate
required CI job so Rust-only local work does not silently waive parity.

The original encoder was manually checked against the `cborg` oracle named by
ADR-C1, including map-key order and the `2^53` and `2^64 - 1` boundaries. That
historical differential run is not a CI gate and `cborg` is not a runtime
dependency. The original dependency inspection counted unsafe occurrences in
`generic-array` (78), `sha2` (29), `cpufeatures` (9), and `block-buffer` (4);
`digest`, `crypto-common`, and `typenum` forbade unsafe code. Those exact
version-dependent counts are historical inspection, not a frozen policy
assertion. SAFE-009 applies to this project's crate, which inherits workspace
`unsafe_code = "deny"` and is checked by the Tier-1 gate.

Scheduled long fuzzing and corpus accumulation are now configured and have
completed successfully; `docs/quality/fuzzing.md` is the current source for
resource limits and remaining Section 11.4 gaps. Parsers that do not yet exist
have no target, and the future release pipeline still needs the zero-untriaged-
crash gate.

The Section 5 domain types, MODEL-002 layering, MODEL-003 public artifact
schemas, and MODEL-004 provenance remain unimplemented. This increment only
settles and implements the collection boundary they must use.

Two repository-summary edits were deferred when this increment was accepted so
that WP-010 would not cross its README sub-file grant: the WP-000 row still
grouped WP-010 with the hand-maintained trace documents, and the accepted-ADR
roster stopped at ADR-C5. A subsequent WP-000-owned follow-up removed the stale
phrase and added ADR-C6 to the roster. The WP-010 row and this document already
reported the generated conversion and accepted decision.
