# WP-L100: Linux read-only inventory and capability adapter

- Spec version: 12.10.0
- Stage: Trustworthy read-only product (M1); the write-capable Linux
  helper that consumes this package is WP-L110's (M3)
- Objective: Deliver the Section 14 charter — the Linux read-only
  inventory and capability adapter — as a pure-read, unprivileged
  library that turns the ordinary Linux client contract into canonical
  domain values: INV-001/002/004/006/008 discovery normalized into
  WP-010's types with a MODEL-004 observation set behind every property,
  short of exactly the values the privileged helper authors,
  ADR-0018's transport classification supplied as the authenticated
  facts the protection closure consumes, LIN-006's detection-only
  representations, and the CAP-004-shaped runtime facts WP-050's engine
  already names this package as the future producer of. The adapter
  reads. It never opens a block device, mounts, unlocks, runs a repair
  tool, branches on privilege, or authors a value the privileged helper
  owns.
- Requirement IDs: INV-001, INV-002 (the reported properties and their
  observation sets; the SAFE-003 identity **record** and its strength
  are not this package's — they bind at validation, for the reason the
  register-gate note below gives), INV-004 (with
  ADR-0033's derivation rule as an imported obligation), INV-006,
  INV-008, LIN-006 (detection, with the multipath arm evidence-gated
  below), CAP-004 (the runtime facts produced, never judged), MODEL-002
  (the layering the topology expresses), MODEL-004 (provenance for every
  property this adapter reports), SAFE-002 (unprivileged, with no
  privilege-conditional branch anywhere), SAFE-004 (any tool the runtime
  facts require is launched through a structured argument array from a
  trusted absolute location — never a shell, never a user-controlled
  `PATH`), SAFE-005 (absence fails closed), SAFE-009 (workspace lint
  inheritance: this crate takes the `unsafe` denial rather than the
  adapter exception, because it opens nothing that would need one).
  **Claimed increment-gated: LIN-001** — UDisks2 as the discovery
  interface, behind its own recorded route decision (the WP-035
  increment-10 and WP-040 transport shape). The contract this package
  delivers reads sysfs and the udev database as ordinary files with an
  empty dependency closure; adopting UDisks2 buys LIN-001's named
  interface at the price of a D-Bus client dependency and an IPC
  surface, and that trade is a recorded choice, never drift.
  Consumed, not claimed: MODEL-005 and the `pce/1` codec (WP-010's), the
  snapshot body schema (WP-010's), CAP-001/003/005/006 (WP-050's engine
  judges the facts this adapter supplies; a qualification row in
  `docs/capabilities/` is that package's reviewed act), INV-003's
  *state* determination (helper-authored under ADR-0014 — this package
  publishes only its contract's reach, per ADR-0013), the protection
  verdict (ADR-0016, helper-authored), INV-005 and INV-009 event
  behavior (no consumer exists; they arrive with the surface that needs
  them), INV-007's diagnostic bundle (WP-035's; this package supplies
  the discovery material it admits), LIN-002's write stack (ADR-L1 and
  WP-L110's — only which file systems this contract distinguishes is
  detection), and every LIN-00x mutation requirement (WP-L110's).
- Prerequisites: WP-000; WP-010 (increments 1–3: the codec, the Section
  5 types, and the snapshot body this adapter fills); WP-020 (increment
  1: the deterministic fixture generator, for images a recorded capture
  is taken over); WP-050 (increments 1–4: the engine whose `RuntimeFacts`
  and `TopologySnapshot` inputs this package produces)
- Test tier: T1, unprivileged, on every platform. Every test drives the
  adapter's injected read seam over a fixture tree: no test opens a
  block device, launches a process, reads the environment, or requires
  Linux to run. Recording a capture from a real host is a separate,
  operator-run act whose output is a committed text fixture — never a
  test that needs hardware.
- Register gates: **two open, both conservative-refused here, neither
  resolvable by this package.**
  - **SI-28 (Mitigated-open, floor in force)** gates any identity-
    strength answer. The conservative answer is structural, and stronger
    than a refusal to classify: **this package emits no `DeviceIdentity`
    at all**, so it derives no strength for SI-28's population to be
    misclassified in. That record carries `table: TableState` as a
    required field whose every variant is a determination about the
    medium — `Present`, `Absent`, and an `Indeterminate` whose two
    causes are `Ambiguous` and `Unreadable` — and INV-003 forbids a
    client that read no table bytes asserting any of them, so an honest
    client record is not constructible in the first place. Identity
    binds at validation from the helper's own re-discovery: the pin
    SI-13's 2026-08-12 sweep verified, every delivered planner path
    emitting empty identity maps. What this package reports is identity
    *material* — each identifier an attributed observation naming the
    interface that produced it — and SI-28's floor inputs among it:
    transport class, removability, and identifier attribution, so the
    layer that owns the floor can compute it. Relaxation stays ADR-0017's
    named revisit condition and its apparatus-qualification evidence.
  - **SI-37 (Open, Later)** gates any relaxation of the unassembled
    unequal-identifier multipath population. ADR-0018's transport arm is
    the fail-closed design home and is delivered; this package supplies
    its inputs and infers no cross-path device sameness of its own
    (ADR-0011). Nothing here moves a closure-blocked population, and the
    per-platform dual-path matrix SI-37's evidence clause requires is
    not this package's to produce.
  - **SI-13** is pinned beyond this package — Later, WP-L110's
    validate-plan surface, verified accurate by the 2026-08-12 residue
    sweep. This package represents aggregates; it makes none of them a
    write target, because it makes nothing a write target.
- Milestone sequencing, recorded so the start is honest: milestones gate
  integration exit, not package start (the WP-035/WP-050/WP-060/WP-070
  precedents under the same sequential rule). M1's exit needs inventory
  correct against fixtures on **all** platforms; this package is one
  platform's half of that, delivers no user-facing surface, and asserts
  no milestone exit by starting.

## Imported verification obligations — the founding duty

Each obligation below was recorded against this package's creation, with
the instruction that the creation cannot omit it. Each is assigned to the
increment that owns it; none is discharged by this document.

**From ADR-0033 (SI-14, derived values are derivations):**

1. This package's INV-004 surface presents free extents and alignment as
   **derivations** — computed at use from the detected inputs they name,
   never stored, carrying no observation set and no confidence of their
   own — and does not present a derivation at all over an input whose
   observation set derives `unavailable` or `conflicting`, surfacing the
   input's own state instead, **with a fixture for each arm**
   (increment 3).

**From ADR-0011 (SI-12, multipath is detection-only):**

2. T1 tests over fixture-backed replay of **recorded** multipath
   enumeration data as regular files — the WP-035 replay pattern —
   asserting one dm node, its member path nodes, the kernel-reported
   membership relation, and `unsupported` with the multipath reason for
   every mutating capability on all of them; and two recorded devices
   presenting equal stable identifiers with no assembled dm node
   yielding SAFE-005 `blocked` on both (increment 4, evidence-gated
   below).
3. The fixture's shape is gated on the multipath observability rows that
   ADR's Consequences demand, because "a replay fixture authored from
   specification text alone would be the failure mode this ADR's own
   Context names." No such row exists today (increment 4's gate, and the
   obligation on WP-035 recorded below).

**From ADR-0013 (INV-003 scoped by privilege):**

4. The INV-003 reach declaration for **this package's own contract**:
   one answer per state, derived from the contract and the platform
   rather than from any device, never derived per-device, never omitted
   when the answer is "no" (increment 1).

**From ADR-0014 and ADR-0016 (the two authored fields):**

5. No partition-table state and no protection verdict is emitted by this
   package on any path — the helper authors both at validation, and the
   facts this adapter supplies leave exactly those positions absent, so
   the closure fails closed where an authored value belongs rather than
   reading a client's guess. The rule reaches the identity record too:
   `DeviceIdentity` carries a required table state, so this package
   emits no such record and the helper builds it from its own
   re-discovery (increments 1–3, structurally).

**From ADR-0018 (SI-11's protection closure, the transport arm):**

6. Transport classification into the closed positive-local list, with
   `Unrecognized` as the fail-closed default and the only answer for a
   class this build cannot positively name (increment 2).

**From ADR-0019 (node naming):**

7. Node addresses are derived positional addresses, never stored; and
   same-kind nodes deriving equal addresses collapse, before encoding,
   into a counted, flagged, indeterminate collision group (increments 3
   and 4).

**From ADR-C4 (MODEL-004's provenance shape):**

8. A positively observed **absence** is a value, not an unavailability —
   held by the observation outcome vocabulary's own shape, so the two
   cannot be conflated by a caller either (increment 1).

**From ADR-C5 (MODEL-002's aggregation model):**

9. An `Aggregate` carries the aggregate's **self-reported** member
   count, never a count of members currently observed (increment 4).

## Evidence sourcing — the rule this package works under

Structural properties — bounds, refusals, closure, unconstructibility,
the absence of a call — may be tested over authored fixture trees, the
shape WP-035's device-source tests already use. Every **representational**
claim about what a real Linux host exposes rests on a capture recorded
from a real host and committed as a text fixture.

Where no recording exists, the increment says so and delivers the
fail-closed answer rather than authoring a fixture from specification
text. ADR-0011 states this for multipath in terms; the rule is general
here because the failure mode is not multipath-specific — a fixture
written from the specification tests that the adapter agrees with the
author's reading of the specification, which is not evidence about any
platform.

## Boundary — surfaces this package must not build

Each prohibition names its governing authority.

- **No mutation, no privilege, no device access.** This is a read-only
  adapter running at Tier 1 under SAFE-002, with no privilege-conditional
  branch: running it as root must produce the same answer as running it
  as anyone else, or the published INV-003 reach becomes a per-user
  statement, which INV-003 forbids. Every Linux mutation requirement
  (LIN-001's authorization half, LIN-002's write stack, LIN-003, LIN-004,
  LIN-005, LIN-007, LIN-009, LIN-010) is WP-L110's.
- **No authored helper values.** Partition-table state is authored by
  the privileged helper from its own raw-sector parser (ADR-0014), and
  the derived protection verdict is authored under ADR-0016 from the
  helper's evidence contract. This package emits neither, on any path.
  MODEL-005's authoring set is closed at exactly those two entries, and
  an adapter that filled either would be the creep that closure exists
  to prevent.
- **No planning basis.** What this package assembles is Section 6's
  client draft snapshot — a **proposal**. The snapshot an authorized plan
  binds is the one HLP-002's re-discovery produces at validate-plan, and
  no surface here may describe its output as a validated planning base
  or as evidence that an undeclared state is absent (INV-003's consumer
  rule).
- **No capability judgment.** CAP-001's conditioning, CAP-003's statuses
  and reasons, and CAP-005's one-engine rule are WP-050's. This package
  produces CAP-004's facts and hands them over; a client capability
  answer is advisory in any case (CAP-007), and nothing here may
  short-circuit the engine or upgrade an answer.
- **No sameness inference.** The product infers no cross-path device
  sameness of its own (ADR-0011, a standing rule since spec 4.3.0).
  Two interfaces reporting a serial produce two attributed observations,
  never one elected identifier and never a claim that two rows are one
  device.
- **No identity record, and therefore no strength.** `DeviceIdentity`
  carries a required table state, and every variant of that field is a
  determination INV-003 forbids this contract making. The record binds
  at validation from the helper's own re-discovery; this package reports
  the material it is built from, attributed per observation. That is
  SAFE-003's and INV-003's arithmetic rather than a posture this package
  chose, and SI-28's floor is honored by the absence rather than by a
  promise.
- **No user-facing surface.** The CLI is WP-035's and WP-080's, the UI
  is WP-030's and WP-090's, and the diagnostic bundle is WP-035's. This
  package is a library.

## Increments

1. **The contract, its seam, and its published reach.**
   `crates/adapter-linux` workspace member (`[lints] workspace = true`,
   `unsafe_code` denied by inheritance, `//!` docs), the injected read
   seam over sysfs and the udev database with the bounded-read
   discipline WP-035 established — a device-count bound and a
   per-value byte bound, each refusing rather than truncating, so a
   partial list is never mistaken for a complete one. The MODEL-004
   observation type: source adapter, adapter version, method, and an
   outcome vocabulary that separates a value, an unavailability reason,
   and a read error — with ADR-C4's rule structural, so a positively
   observed absence cannot be encoded as an unavailability by anyone.
   The INV-003 reach declaration for this contract under ADR-0013, with
   a source-text test that the reach module cannot name the device seam
   at all. Converts the traceability mode to `generated`.
2. **Devices and their identity material (INV-001, INV-002, ADR-0018).**
   Whole-device enumeration reported as attributed observations: model,
   vendor, transport, removability, capacity, both sector sizes,
   read-only status, and every identifier the contract exposes, each
   carrying its own observation set naming the interface that produced
   it — two interfaces reporting a serial produce two observations, and
   nothing here elects one. Transport classification into ADR-0018's
   closed positive-local list, `Unrecognized` the fail-closed default and
   the only answer for a class this build cannot positively name. **No
   `DeviceIdentity` is constructed**, held by a test over the crate's
   public surface: that record carries a required table state this
   contract may not determine, so it binds at validation instead, and
   SI-28's gate is discharged by the absence. SI-28's floor inputs are
   reported as facts; no cross-device sameness is inferred anywhere.
3. **The topology, and INV-004's derivations (ADR-0019, ADR-0033).**
   Partitions, volumes, file systems, encryption layers, and mounts
   assembled into a `Topology` under ADR-0019's derived positional
   addresses, equal-address same-kind nodes collapsing into the counted,
   flagged, indeterminate collision group; `BackingSignature` nodes for
   FS-004 signatures including the observed-signature-without-observed-
   aggregate case INV-008 names; an unrecognized variant carried for
   every closed enum over externally observed values; the `Captured`
   snapshot assembled as Section 6's client draft proposal, its facts
   carrying no table-state entry at all, so the closure fails closed at
   exactly the position the helper's authored value occupies rather than
   reading a client's guess. **ADR-0033's imported obligation lands
   here**, with its fixture for each arm.
4. **LIN-006's detection layer.** Device mapper, loop devices with
   their ADR-0019 host-backing edges, Btrfs multi-device as one
   `FileSystem` over n ≥ 1 backings, LVM/mdraid/LUKS members as
   signatures and aggregates carrying ADR-C5's self-reported member
   count, and active root/boot/swap dependencies. **The multipath arm
   opens only when its evidence exists** — obligations 2 and 3 above.
   Until then this increment delivers everything else and the adapter
   answers the multipath population with increment 2's fail-closed
   classification.
5. **The capability seam and the record.** `RuntimeFacts` produced in
   CAP-004's shape for Linux — tool presence and version state under
   SAFE-004's structured-argv, trusted-absolute-path discipline, and the
   Section 9 floor determination for the Debian/Ubuntu and Arch tiers —
   handed to WP-050's engine, which judges them. INV-006 held
   structurally, with a test pinning the absence of every mount, unlock,
   and repair-tool call. INV-007's discovery material offered through the
   field allowlist WP-035's bundle applies. Package record sweep: README
   row, CHANGELOG, generated traceability current.

Beyond these five: LIN-001's UDisks2 route decision; the multipath
fixture when its observability rows land; INV-005 and INV-009 event
behavior when a consumer exists to drive invalidation; and the mutation
requirements, which are WP-L110's under its own assignment.
