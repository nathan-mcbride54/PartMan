# WP-060: Pure planner, extent solver, risk model, simulated topology, reversal plans

- Spec version: 12.4.0
- Stage: Planning and dry run (M2)
- Objective: Deliver the pure planning library the Section 14 charter
  names: a deterministic, side-effect-free computation (PLAN-001) from a
  captured snapshot, capability answers, and a typed request to an
  `OperationPlan` — steps in an acyclic dependency graph with conflicts
  explained (PLAN-003), extents solved alignment-conservatively, and the
  simulated final topology emitted beside the original (PLAN-002)
  through the same fail-closed constructors that built the capture. The
  planner decides nothing the register holds open and constructs nothing
  the domain's sole constructors do not: every step goes through
  `PlanStep::mutating`, every plan through `OperationPlan::assemble`,
  and every capability answer is advisory input (CAP-007) — the closure,
  not the answer, is what refuses a step.

## Boundary — surfaces this package must not build

Each prohibition names its governing authority.

- **No step outside the sole constructor.** Every mutating step is
  `PlanStep::mutating` over the capture's authenticated facts — the same
  closure, the same acknowledgment law (ADR-0012, ADR-0018). The planner
  sequences and solves; it never re-implements, caches, or bypasses the
  refusal machinery, and a capability answer cannot admit a step the
  closure refuses (CAP-007 both ways).
- **No verdicts, no facts, no snapshots of its own.** Protection is the
  domain's; capability answers are WP-050's; captured snapshots arrive
  decoded from the typed boundary. The simulated topology is built
  through `TopologySnapshot::assemble` with `SnapshotKind::Simulated` —
  the schema string that can never be a planning base or satisfy a
  PLAN-006 comparison, structurally (3c's rule).
- **No register answer by construction.** Every gate this assignment
  named is now cleared: SI-19 (ADR-0022, spec 12.0.0), SI-15
  (ADR-0023, 12.1.0), SI-16 (ADR-0024, 12.2.0), SI-17 (ADR-0025,
  12.3.0), and SI-24 (ADR-0026, 12.4.0). Their increments open under
  recorded decisions rather than under guesses — implementing a
  decided answer is not answering. SI-15's delivered refusal was
  replaced by ADR-0023's decided behavior in increment 5; SI-17's
  withheld combination stands in code until its unlock increment
  lands, and SI-16's backup step family stays unbuilt until its own
  reviewed increment — each citing a decision now rather than an open
  question.
  The principle outlives the empty list: any newly filed gate is
  conservative-refused, never silently answered.
- **No hashed-body change.** The plan body schema is WP-010's. A
  vocabulary this package delivers that must enter the body (PLAN-005's
  cancellation class, eventually PLAN-008's reversal linkage) lands as a
  jointly-sequenced WP-010 schema change under WP-010's grant, with the
  MODEL-003 version discipline that file owns.
- **No platform reach, no apply, no elevation.** Pure computation over
  supplied values, exactly like the engine it consumes.

## Increments

1. **The request vocabulary and the pure chassis.** `crates/planner`
   workspace member (workspace lints, `unsafe_code` denied by
   inheritance), depending on `partman-domain` and `partman-capability`
   deliberately. A typed plan request (operation, target, parameters as
   decided vocabularies permit), the planning entry point's shape, and
   the conditioning rule: a request whose capability answer is
   `unsupported` or `blocked` refuses with that answer carried verbatim
   (ACC-009's planner half — the reason and remediation travel, never
   re-derived), `preview` permits planning, and `supported` is not a
   distinct planning state (it differs from `preview` at apply, which
   does not exist here). PLAN-001's determinism held by test: equal
   snapshot, answers, and request produce byte-equal plan bodies.
   Converts the traceability mode to `generated`.
2. **The step graph.** PLAN-003: steps as an acyclic dependency graph
   in the body's semantic order, cycles and conflicts refused as typed
   values that explain the conflict — which two steps, which resource,
   which rule — never as a boolean. Multi-step requests sequence through
   the graph; every step still constructs individually through the sole
   constructor against the capture.
3. **The extent solver, alignment-conservative.** Free-extent
   computation from the snapshot's authenticated extents; placement at
   PART-004/PART-005's 1 MiB default alignment with published-geometry
   deviation only as those texts permit; size and fit refusals typed and
   explained. **SI-15's case — a pre-existing misaligned partition whose
   growth would force realignment or an unrequested move — refuses with
   a typed conflict naming the register gate**, as delivered while the
   gate held. (The gate has since resolved — ADR-0023, spec 12.1.0 —
   and increment 5 replaced the refusal with the decided behavior.)
4. **The simulated final topology and the record.** PLAN-002: apply the
   step graph's effects to the capture through
   `TopologySnapshot::assemble(Simulated, ...)`, emitting both
   topologies; the simulated body round-trips the typed boundary and can
   never satisfy a PLAN-006 comparison (held by the existing 3c
   property, re-asserted here at the planner's boundary). Package record
   sweep: README row, CHANGELOG, generated traceability current.
5. **The solver unlock (SI-15, ADR-0023, spec 12.1.0). Delivered
   2026-08-12.** A deviation is an act: the solver judges only
   boundaries the plan authors, and the misaligned-growth refusal is
   replaced by the decided behavior. The 63-sector grow-at-tail case
   authors only the aligned new end with the untouched start carried as
   a typed inherited fact in the plan's consequence material
   (planner-layer carriage; the hashed consequence-text vocabulary
   remains a later jointly-sequenced body change, and ADR-0023 rejected
   typed hashed carriage of alignment facts); grow-to-fill against a
   misaligned neighbor is conformant and recorded as coincident naming
   the edge; the §11.2 authored/inherited split is held by test over
   the shrink path; and the no-fourth-state property is swept — every
   authored end the solver accepts is aligned or coincident, everything
   else refuses typed (`UnalignedAuthoredBoundary`, naming the nearest
   conforming values), with authored-end policy now enforced on
   create and shrink ends too, closing the fourth state those paths
   previously left open. The deviation-override vocabulary stays
   deliberately inexpressible. Each new gate was mutation-verified
   (four mutants, each failing a named test).
6. **The reversal (PLAN-008, ADR-0022, spec 12.0.0). Delivered
   2026-08-12**, on the jointly-sequenced WP-010 slice-3l plan-body v2
   change (its own reviewed PR, landed immediately before under
   WP-010's grant). Every plan now emits PLAN-008's output: the sized
   create and grow emit truthful reversal drafts — the create's
   deleting the created structure through a step-output reference
   (never an address; the node does not exist yet) with the created
   node's emptiness as its precondition, the grow's shrinking back with
   the reclaimed tail's emptiness judged in the target's own address
   space — and every other plannable operation states per-step,
   machine-readably, why reversal is impossible (destroyed bytes;
   uncarried prior values). The forward body carries the linkage (draft
   by ID and body hash, or the statements); the draft proposes the
   simulated final topology and binds at its own validation against a
   real capture — resolving after apply, refusing before, refusing the
   prediction itself, and refusing by precondition once data lands
   (truth decay, the named fixture, end to end at the planner). PLAN-001
   holds over the draft as bytes. The Reversible claim is made exactly
   where the truthful draft exists — the sized create — and the grow
   deliberately keeps its conservative severity: no draft, no
   Reversible is one-directional. ADR-0022 verification items 1–5
   discharged between the two changes; item 6 (the reversal's own
   ADR-0021 authorization) is the authorization surface's, recorded
   here as a boundary. Four planner-side mutants each failed a named
   test.
