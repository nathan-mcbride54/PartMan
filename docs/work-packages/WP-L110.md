# WP-L110: Linux helper, GPT/MBR, file systems, polkit

- Spec version: 19.0.0
- Stage: Trustworthy write path (M3). Created 2026-08-19 on the arc plan
  `docs/reviews/WP-L110_ASSIGNMENT_PLAN_2026-08-19.md` (taken by the
  decision owner: `services/helper-linux/` as the path; LIN-003…007 and
  LIN-010 as later increments behind their own rounds, claimed nowhere
  yet).
- Objective: Deliver the Section 14 charter — the Linux privileged
  helper — as the process that is reached over the Linux transport
  (WP-040 increment 5, ADR-0055), accepts exactly HLP-001's six
  operations and nothing else, **independently re-discovers** the
  topology before the first write (HLP-002: the adapter's client contract
  run as root plus ADR-0018's byte layer over read-only device handles)
  and authors the two values nothing below it may — the table state
  (ADR-0014) and the protection verdict (ADR-0016) — validates plans
  over that authoritative snapshot with WP-050's engine and WP-060's
  planner, enforces ADR-0021's two-tier ladder (a floor act per apply
  consumed through WP-070's journal; polkit `auth_admin` without retained
  grants at ≥ Disruptive or any step flag), and executes admitted plans
  through WP-070's state machine and journal: GPT/MBR table writes and
  file-system operations per installed capability, through a SAFE-004
  launcher, under CONC-001 device locking, with cancel and resume. The
  helper integrates; it re-implements nothing delivered below it, and it
  never accepts a path, a command, or a client-asserted fact as an input
  to authorization.
- Requirement IDs: HLP-001, HLP-002, HLP-003, HLP-004, HLP-005, HLP-006,
  HLP-007; LIN-002 (GPT/MBR and the listed file systems "according to
  installed capabilities" — capability-gated, never assumed); LIN-009
  (polkit rules scoped to validated plan execution); CONC-001, CONC-002,
  CONC-003, CONC-004, CONC-005 (the helper is the serialization point);
  SEC-002 (replayed, expired, altered, cross-user, cross-device plans
  rejected); SEC-009 (the local audit log); PLAN-006 and PLAN-007
  (enforced, not defined); RPC-006's reattach *behavior* (the protocol
  half is WP-040's; the journal WP-070's; both exist, so the behavior
  binds here); SAFE-002 (context 1 — this is the one privileged process),
  SAFE-004 (every tool through the launcher), SAFE-005, SAFE-006, SAFE-009
  (a helper crate may carry reviewed `unsafe`; none is planned — HLP-002's
  device reads are `std::fs::File`). **Claimed increment-gated, three
  route decisions, none decided by drift:** (a) the launch and endpoint
  ownership route (who creates the `0711` directory and the per-user
  `0600` node, and how the helper comes to exist — ADR-0055 T5/T6 and
  LIN-009 in the room), before increment 1; (b) LIN-001's
  authorization/mutation half (ADR-0054: UDisks2, libblockdev or
  authoritative native tools; the UDisks2 ≥ 2.9 tool floor enters the
  CAP-006 store with the first invoker), before increment 4; (c) the
  launcher's home (WP-035's `SystemLauncher` is in `apps/cli`; a helper
  cannot depend on an app), before increment 4, with WP-035 in the room.
  Consumed, not claimed: every type and function below the helper
  (WP-010's domain and codec, WP-050's engine, WP-060's planner, WP-070's
  journal and state machine, WP-040's protocol and transport, WP-L100's
  adapter, the table parser); CAP-006 qualification rows (WP-050's
  reviewed act — this package *produces* the first tool invocations those
  rows qualify); LIN-008 (signed packages — `packaging/`); LIN-003…007
  and LIN-010 (LUKS, LVM, mdraid, dm/multipath operations, GRUB,
  fstab/crypttab verification — later increments or packages behind their
  own rounds, SI-13 among the gates); UI-011's display of the tier
  (WP-090's; this package reports it).
- Prerequisites: WP-000; WP-040 (increments 1–5: the protocol and the
  Linux transport); WP-060 (the planner and its refusals); WP-070
  (increments 1–5: the state machine, the journal, the apply lifecycle);
  WP-L100 (increments 1–5b: the client draft, the held standing, the
  runtime facts and the floor); WP-010's table parser.
- Test tier: T1, unprivileged, on every platform for the pure seams (the
  closed operation set, the refusal arms, the lifecycle over in-process
  pairs and authored journals) — no Tier-1 test opens a block device,
  launches a process, needs elevation, or needs Linux; the Linux-only
  legs are gated in the body and assert the typed unsupported-platform
  refusal elsewhere (the `ffi-linux-loop` and `transport-linux`
  precedent). **T2** for everything representational and everything that
  writes: disposable guests in the r-series shape on WP-020's fixture
  images, root as the setup actor, unprivileged users as the clients,
  never a workstation disk (SAFE-001, SAFE-007), each sitting recorded
  with its transcript digest.
- Register gates: **three, all inherited, one biting by name.**
  - **SI-13 (Later, before WP-L110's validate-plan surface)** — identity
    binding for pool and array write targets. The conservative answer is
    structural: validate-plan refuses any plan whose target is an
    `Aggregate` (no binding constructor for aggregates) until a round this
    package files decides; increment 2 shipped the refusal (2026-08-19:
    no wire spelling, plus the typed arm), not the decision.
  - **SI-28 (Mitigated-open, floor in force)** — the adapter's client
    records stay `Weak`; this package's re-discovery is the first place a
    positively determined partition-table state exists, so `Strong` is
    reachable here **by SAFE-003's own terms** and nowhere else. That meets
    the floor; it relaxes nothing, and ADR-0017's revisit condition
    stands.
  - **SI-37 (Open, Later)** — multipath detection-only holds; a mutating
    operation on a multipath device or recognized member is `unsupported`
    (ADR-0011), and this package infers no cross-path sameness.
- Milestone sequencing, recorded so the start is honest: milestones gate
  integration exit, not package start (the standing precedent). M3's
  exit needs a live helper on ≥ 1 platform behind WP-080's apply
  surface; this package is that platform's helper and asserts no
  milestone exit by starting.

   verified by the transport before any byte is read; a non-local or

## Evidence sourcing — the rule this package works under

The WP-L100 rule, extended to the privileged layer: structural properties
(closure of the operation set, refusal arms, one-act-one-apply, bounds,
locking) may be tested over authored inputs, in-process pairs and
authored journals; every **representational** claim about a real Linux
host — what polkit answers, what a device's bytes classify to, what a
tool prints, what a kernel does on a write — rests on a recorded capture:
a `docs/quality/observability.md` row (WP-035's, filed in the two-act
bracket) or a Tier-2 transcript from a disposable guest archived with its
digest. Where none exists the increment delivers the fail-closed answer
and says so. Nothing in this package writes to a device outside SAFE-001's
disposable environments.

## Boundary — surfaces this package must not build

Each prohibition names its governing authority.

- **No operation outside HLP-001's six**, no raw command, no path
  execution (RPC-005, CLI-004).
- **No authorization from connection standing, cache or session**
  (HLP-003, ADR-0021); no client-asserted capability or tier (CAP-007).
- **No discovery through UDisks2** (ADR-0054); whatever the toolset round
  decides is the *mutation* side.
- **No write outside an admitted plan's steps**, and none outside
  SAFE-001's disposable environments in any test (SAFE-001, SAFE-007).
- **No network socket** (SEC-007); no transport of its own (WP-040's).
- **No journal, planner, engine or adapter re-implementation** — the
  helper calls what is delivered.
- **No LUKS, LVM, mdraid, multipath-mutating, GRUB or fstab operation**
  until its own round and increment (LIN-003…007, LIN-010; SI-13).
- **No package, unit file or polkit policy shipped as product** until the
  launch round decides (LIN-008 is `packaging/`'s).
