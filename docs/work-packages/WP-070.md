# WP-070: Journal and execution state machine

- Spec version: 12.9.1
- Stage: Planning and dry run era (M2 per Section 14; the write-capable
  helpers that consume this package are WP-W110/WP-L110/WP-M110's, M3)
- Objective: Deliver the Section 14 charter — the journal (JRN-001…006)
  and the execution state machine (Section 8) — as pure, portable
  libraries: the append-only checksummed journal with monotonic
  sequencing, torn-tail recovery, idempotent replay, and
  liveness-scoped retention; and the plan-lifecycle state machine whose
  published transition table is machine-readable and whose undeclared
  transitions are unrepresentable. This package is born with **an empty
  register-gate list**: every spec issue that would have gated it —
  SI-20 (ADR-0027), SI-21 (ADR-0028), SI-22 (ADR-0029), SI-23
  (ADR-0030) — was resolved before this assignment was created, and
  four ADRs recorded verification obligations naming this package in
  advance. Importing those obligations is a founding duty of this
  assignment, enumerated below, so the machinery is built to decided
  semantics rather than guesses.
- Requirement IDs: JRN-001, JRN-002 (the durability rule as a typed
  seam; real platform durability is exercised by the helper packages'
  acceptances), JRN-003, JRN-004 (liveness-scoped retention per
  ADR-0029), JRN-005, JRN-006 (the versioned journal schema under
  MODEL-003), Section 8 (states, transition table, terminal effect
  summaries, the two-arm RecoveryRequired exits per ADR-0027, the
  apply-lifecycle definition per ADR-0028), SAFE-009 (workspace lint
  inheritance; the journal crate is on the unsafe-forbidden list).
  Consumed, not claimed: MODEL-005/`pce/1` (WP-010's codec), HLP-*
  behavior (the helper processes are WP-W110/L110/M110's; this package
  defines the records and machine they must honor), PLAN-006/PLAN-007
  (WP-010's boundary, read by the lifecycle rules), RPC-006's
  journal-reconstruction half (binds when both exist, as WP-040's
  assignment already records), REC-* (WP-R100's, beyond the state
  machine's own edges), SEC-009 (audit-log policy; this package
  enforces only the correctness floor ADR-0029 fixed).
- Prerequisites: WP-000; WP-010 (increments 1–2 at minimum — the
  canonical codec the record schemas encode through; increment 3's
  body formats where records reference bodies); WP-040 (increments
  1–4, the protocol layer; no transport is required by a pure library)
- Test tier: T1, unprivileged. Both crates are pure libraries: no test
  opens a device, launches a process, reads the environment, touches
  the network, or performs real fsync — durability is a typed seam
  exercised over injected fakes, and the platform truth of that seam
  is the helper packages' acceptance obligation, stated here so the
  boundary is honest.
- Register gates: **none open at creation** — the first package born
  with an empty list, because its questions were decided first. The
  standing principle survives the empty list: any newly filed gate is
  conservative-refused, never silently answered.
- Milestone sequencing, recorded so the start is honest: milestones
  gate integration exit, not package start (the WP-035/WP-050/WP-060
  precedents). Nothing here integrates a surface: no helper process
  exists to journal for, and the first live consumer arrives with a
  platform helper package. Starting this package asserts no milestone
  exit.

## Imported verification obligations — the founding duty

Each obligation below was recorded in an ADR against this package's
creation, with the instruction that the creation cannot omit it. Each
is assigned to the increment that owns it; none is discharged by this
document.

**From ADR-0027 (SI-20, the two-arm recovery exit):**

1. The machine-readable transition table's property tests prove exactly
   the published transitions representable (increment 1).
2. The disposal ordering: a recovery plan's apply is unreachable while
   the original's Failed record is not durable; on a shared device set,
   structurally unreachable via HLP-005 (increments 3 and 5; the
   HLP-005 half binds when a helper exists and is re-recorded for the
   platform packages).
3. The linkage chain: a Failed-by-recovery-selection terminal carries
   the recovery plan's ID, and a crash replay reconstructs the chain
   from the journal alone (increments 3 and 4).
4. The roll-forward edge derives its state from journal plus fresh
   re-discovery — JRN-003's rule tested on this edge by name
   (increment 5; the fresh-re-discovery input is a seam here).

**From ADR-0028 (SI-21, the apply lifecycle):**

5. A resume on each of the three re-entry edges traces to the original
   act through an unbroken journal chain, and a broken chain refuses
   (increment 5).
6. A re-entry past the PLAN-007 window is rejected, and a fresh act
   against a fresh snapshot readmits the same apply — two acts, one
   apply, journaled as such (increment 5).
7. One act can never admit a second apply of the same plan or any
   apply of another plan (increment 5).
8. A helper restart mid-apply holds no authorization state the journal
   does not — the hand-forged in-memory-grant test (increment 5).

**From ADR-0029 (SI-22, liveness-scoped retention):**

9. A retention pass over a journal holding a non-terminal apply
   reclaims nothing of that apply or its linkage closure (increment 4).
10. Budget exhaustion is a journaled failure through existing Section 8
    edges; no code path reclaims a live record, structurally
    (increment 4).
11. Replay classifies every gap — compaction-covered proceeds, torn
    tail truncates, anything else refuses — with the mid-chain-gap
    fixture as the named corruption case (increments 2 and 4).
12. Sequence monotonicity holds across rotation and compaction
    (increment 4).
13. ADR-0028's chain-tracing test passes over a journal compacted
    around the live apply — the reconciliation fixture (increments 4
    and 5).

**Record-vocabulary obligations from ADR-0021/0022/0024/0026/0030,
landing with JRN-006 (increment 3):** the authorization-act record
(ADR-0021/0028); the disposal-linkage record (ADR-0027); the
three-variant protection record (ADR-0024, jointly sequenced); the
compaction record and per-apply budget (ADR-0029); protection-artifact
references by content hash only, bytes structurally absent (ADR-0030);
and the helper-computed authorization tier and dry-run refusal classes
as response-data vocabulary consumed from validate-plan surfaces
(ADR-0021/0026 — the enforcement is the helper packages'; the record
classes are this package's).

## Boundary — surfaces this package must not build

Each prohibition names its governing authority.

- **No helper process, no privilege, no device I/O.** The helpers are
  WP-W110/WP-L110/WP-M110's (Section 14); this package defines the
  records and the machine they honor, and runs entirely at Tier 1
  (SAFE-002).
- **No transport, no endpoint.** WP-040's route decisions gate every
  transport; RPC-006's reconstruct-from-journal behavior binds when
  both halves exist, exactly as WP-040's assignment records.
- **No plan semantics.** Plan bodies, validation, severity, and
  authorization tiers are WP-010/WP-060's and the ADRs'; this package
  journals what they decide and never re-derives it.
- **No recovery behavior beyond the machine's own edges.** REC-*
  surfaces and the recovery-action vocabulary are WP-R100's; this
  package carries the references and the exits. *(Until 2026-08-20 this
  sentence also assigned the protection-artifact store to WP-R100 —
  a package that still has no assignment. The increment-4b opening
  round (`docs/reviews/LINUX_4B_OPENING_ROUND_2026-08-20.md`, decision
  1) moved the store class here: this package owns the sibling journal
  discipline the store inherits, and every platform helper consumes it
  exactly as it consumes the journal. The store grant below carries
  ADR-0030's obligations; a restore remains an identity-validated plan
  and the recovery *behavior* remains WP-R100's.)*

  **The protection-artifact store grant (2026-08-20).** This package
  reserves `crates/artifact-store/**` and `schemas/artifact-store.md`:
  the ADR-0030 store class — helper-owned at runtime, inheriting
  JRN-004's admin-protected documented-location clause, sibling to and
  never inside the journal, hash-only references on every surface, the
  ADR-0029 liveness retention rule, the consequence-stated end of life
  — serving PART-013's parse-level table backups (WP-L110 increment
  4b's immediate consumer, per ADR-0024's arms), and later REC-011's
  encryption-header artifacts. Each helper's per-OS on-disk path lands
  under that helper's own grant. ADR-0030's four verification
  obligations import with the grant, as that ADR requires of the
  assignment that takes the store: (1) the artifact's bytes absent
  from every SAFE-006 surface, journal record and plan body, the hash
  reference present where the bytes are not; (2) a retention pass
  reclaims no artifact whose creating apply or referencing closure is
  non-terminal; (3) a restore constructs only as an identity-validated
  plan (REC-001) at its own authorization tier, a raw store read
  outside the helper structurally impossible per platform; (4) the
  end-of-life surface states both consequences and is never silent in
  either direction. The store increment itself — schema and crate,
  Rust, its own WP-020 sitting — is commissioned by the opening
  round, defined by its own act, and sequences before WP-L110
  increment 4b's `Protecting`.
- **No audit-log policy.** SEC-009's retention is the user's; this
  package enforces the ADR-0029 correctness floor and nothing beyond
  it.
- **No real durability claims.** JRN-002's fsync-before-write is a
  typed seam here; asserting platform durability is the helper
  packages' acceptance work, and this document says so rather than
  letting a pure test read as a platform proof.

## Increments

1. **The state machine, pure.** `crates/statemachine`: the thirteen
   states, the transition table exactly as Section 8 publishes it,
   terminal effect summaries, the machine-readable table in
   `schemas/state-machine.md` generated from the same source the type
   checks — and the Section 11.6 property tests proving undeclared
   transitions unrepresentable (obligation 1), with the ADR-0027
   two-arm reading carried as row documentation. Converts the
   traceability mode.
2. **The journal core.** `crates/journal`: append-only records with
   per-record checksums and monotonic sequence numbers, torn-tail
   detection and safe truncation (JRN-001), the JRN-002 durability
   seam as a typed injected boundary, idempotent replay (JRN-003), and
   the three-way gap classification with the mid-chain-gap fixture
   (obligation 11's core).
3. **The record vocabulary under JRN-006.** The versioned journal
   schema (MODEL-003) carrying the imported record classes: transition
   and checkpoint records, the authorization-act record, the
   disposal-linkage record, the three-variant protection record, the
   compaction record, and hash-only protection-artifact references —
   with the WP-010 joint sequencing each ADR names, and the
   secrets-absence sweep (JRN-005, the WP-035 redaction-gate shape).
4. **Retention and compaction.** The liveness-scoped exemption with
   its linkage closure, the per-apply budget with fail-closed
   exhaustion, compaction records legitimizing reclaimed ranges,
   monotonicity across compaction — obligations 9, 10, 11, 12, and
   13's fixture.
5. **The apply lifecycle, enforced at the library layer.**
   Journal-chain tracing on the three re-entry edges, past-window
   rejection and two-acts-one-apply readmission, one-act-never-two-
   applies, and the no-process-state property — obligations 2 (the
   ordering half), 4, 5, 6, 7, and 8, each over injected seams, each
   re-recorded for the platform packages where a live helper must
   demonstrate it.

Beyond these five: nothing is startable here without a consumer — the
first platform helper package re-takes the seam-level proofs against
its real transport, privilege, and durability, under its own
assignment.
